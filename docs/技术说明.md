# Space 项目技术说明

> 本文档说明各系统的运行方式、数据流，以及每个脚本中可调参数的作用与修改方式。
> 引擎：Godot 4.7（Forward+ / d3d12）。所有物理坐标使用**米**，显示坐标由换算层映射到像素。

---

## 1. 项目总览

### 1.1 目录结构

```
space/
├─ scenes/                场景（按功能分类）
│  ├─ game/               main.tscn（主场景）、star_map_demo.tscn（双星试玩入口）
│  ├─ ui/                 菜单、对话、手册、仪表、飞行面板等 HUD
│  ├─ navigation/         星图视图
│  ├─ ships/              飞船场景
│  ├─ world/              行星、城市、小行星、太空垃圾
│  ├─ ports/              港口视图、船坞、事件卡、人物散列网格与委托领取面板
│  └─ audio/              背景音乐、按钮音效（autoload 场景）
├─ scripts/               脚本（与 scenes 同名分层）
├─ data/                  数据 JSON（玩家配置、行星港口、教程、任务、手册、CG）
├─ maps/                  地图 JSON
├─ assets/                素材（图片、音频、手册插图、CG 图）
├─ tools/                 独立工具（地图编辑器、事件与委托编辑器、纹理表构建）
├─ tests/                 测试脚本（res://tests/*_test.gd）
└─ project.godot
```

### 1.2 全局 Autoload（单例）

| `名称`              | `脚本`                                  | `职责`               |
| ----------------- | ------------------------------------- | ------------------ |
| `SaveManager`     | `scripts/persistence/save_manager.gd` | `存档读写、自动保存、场景切换拦截` |
| `BackgroundMusic` | `scenes/audio/background_music.tscn`  | `全局背景音乐`           |
| `UIClickSound`    | `scenes/audio/ui_click_sound.tscn`    | `全局按钮点击音效`         |

### 1.3 核心架构思想

- **物理与显示分离**：飞船/天体用 `flight_position`（米）做物理计算，`global_position`（像素）只做显示。`main.gd` 的 `_view_scale()` / `_to_screen()` 负责换算，显示映射永不写回物理坐标。
- **固定步长模拟**：`SIM_STEP = 0.25s`，每物理步以 `TIME_SCALE = 20.0` 倍速推进，保证跨帧结果一致。
- **UI 与业务分离**：港口 `PortSession` 是纯数据模型，`PortView` 只渲染快照；任务/教程只观察“已提交”的信号，不读取按钮。
- **事件驱动**：`main.gd` 发出 `propulsion_committed`、`ship_selected`、`simulation_step_committed` 等信号，任务与教程订阅这些信号，游戏世界代码不直接调用剧情。

## 2. 全局数据流总览

```
[玩家输入] 按键/按钮/仪表/星图点击
      │
      ▼
[main.gd] _unhandled_input / _start_thrust / _set_throttle / _set_thrust_direction ...
      │  更新 ship 的意图状态（manual_thrust / steering / thrust_direction / maneuver_commands）
      ▼
[main.gd] _physics_process 固定步循环
      │  每 SIM_STEP：引力叠加 _integrate → 推进/修向 → 碰撞扫掠 → 燃料扣减
      │  提交后发 propulsion_committed(forward_delta_v)
      ├──────────────► [task_manager.gd]   首次正向加速 → 入队对话
      ├──────────────► [tutorial_controller.gd] 教程步骤判定
      ▼
[_sync_visuals()] 把米坐标映射回像素，更新星球/飞船/轨迹/按钮
      │
      ▼
[港口] 停靠 → PortController.enter_port → PortSession(模型) → PortView(渲染快照)
[存档] SaveManager.make_snapshot → 序列化到 user:// 文件
```

## 3. 游戏主循环与模拟

### 3.1 `scripts/game/main.gd`（核心，extends Node2D）

**职责**：管理舰队注册、模拟主循环、引力/碰撞/推进/轨道、港口与入轨确认、UI 状态同步。这是全项目最核心的脚本。

**信号（供外部系统订阅）**：

| 信号                          | 参数                                | 含义                                                                                                  |
| --------------------------- | --------------------------------- | --------------------------------------------------------------------------------------------------- |
| `propulsion_committed`      | `vessel, forward_delta_v, source` | 真实物理步提交后发出；`forward_delta_v` 是沿速度/航向的正向 Δv 分量，`source` 为 `manual_button` / `directional_thrust` / 空 |
| `ship_selected`             | `vessel, player_initiated`        | 选中飞船                                                                                                |
| `simulation_step_committed` | `vessel`                          | 每固定步提交                                                                                              |

**关键参数（`@export` 与常量）**：

| 参数                                                   | 默认值          | 作用                                                         | 修改方式               |
| ---------------------------------------------------- | ------------ | ---------------------------------------------------------- | ------------------ |
| `layout_origin`                                      | `(440, 360)` | 编辑器布景原点（像素），对应模拟世界零点，仅首次初始化换算用                             | 编辑器 Inspector 或脚本  |
| `layout_pixels_per_meter`                            | `0.004`      | 编辑器布局的像素/米换算，仅初始化用，不影响运行时物理                                | 同上                 |
| `DOCK_SPEED_TOLERANCE`                               | `0.1`        | 泊船速度容差（m/s），速度 ≤ 此值才能泊船                                    | 改常量                |
| `SIM_STEP`                                           | `0.25`       | 固定物理步长（模拟秒），越小越精确但更耗 CPU                                   | 改常量（与预览、存档校验耦合，谨慎） |
| `TIME_SCALE`                                         | `20.0`       | 模拟倍率，每真实帧推进 delta × TIME_SCALE                             | 改常量                |
| `PREVIEW_SECONDS`                                    | `620.0`      | 近域视角轨迹预演时长（模拟秒）                                            | 改常量                |
| `PREVIEW_REFRESH_INTERVAL`                           | `0.1`        | 预演刷新节流间隔（真实秒）                                              | 改常量                |
| `PREVIEW_STEPS_PER_FRAME`                            | `400`        | 每帧预演最多推进的步数（防止卡顿）                                          | 改常量                |
| `allow_builtin_map`                                  | `false`      | 无 `user://` 地图时是否回退打包内置 `maps/default_map.json`（游戏入口开启）    | 场景 Inspector       |
| `INITIAL_FUEL` / `START_POSITION` / `START_VELOCITY` | 见代码          | 旧常量；实际起始值由 `ship.gd` 的 `initial_fuel/position/velocity` 决定 | 以 ship 参数为准        |

**主要方法**：

| 方法                                                                                             | 作用                                                                              |
| ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| `_physics_process(delta)`                                                                      | 主循环：注册校验 → 累加 accumulator → 每 SIM_STEP 更新障碍物与飞船 → 碰撞 → 燃料 → 轨道资格 → 预演 → UI |
| `_integrate(pos, vel, step)`                                                                   | 引力叠加 + 半隐式欧拉积分 + 行星/城市碰撞裁剪，实飞与预览共用                                              |
| `_propulsion_step(...)`                                                                        | 沿速度/航向方向的顺逆推，`accel_command` 正加速负减速                                             |
| `_steering_step(...)`                                                                          | 方向油门修向（`thrust_direction` + `thrust_throttle`）                                  |
| `_start_thrust(dir)` / `_set_throttle(v)` / `_set_thrust_direction(d)` / `_set_thrust_lock(b)` | 推进/油门/方向/夹角锁的意图入口（暂停时可预设）                                                       |
| `_verify_arrival_orbit(...)`                                                                   | 用真实积分器预演一圈判定是否稳定绕行                                                              |
| `_dock_city` / `_confirm_arrival` / `_depart`                                                  | 城市泊船、行星入轨确认、起航                                                                  |
| `_rollback_reason()` / `_rollback_to_departure()`                                              | 卡死判定（撞毁 / 燃油耗尽且未入轨）与回档到上次起航                                                  |
| `_reset()`                                                                                     | 重置航行（取消教程、清通知、恢复初始状态）                                                           |

### 3.2 `scripts/game/star_map_demo.gd`（extends main.gd）

双星试玩入口，仅覆盖演示初始条件：自动选中第一艘船、设置导航参考点、默认打开星图。**不改变任何航行规则**。

## 4. 飞船系统

### 4.1 `scripts/ships/ship.gd`（extends Node2D，`@tool`）

每个飞船实例独立保存航行状态。以下参数均在编辑器 Inspector 中可改（`@export`）：

| 参数                               | 默认值              | 作用                                   | 修改方式      |
| -------------------------------- | ---------------- | ------------------------------------ | --------- |
| `display_name`                   | `"运输船"`          | 舰队选择栏与 UI 显示名                        | Inspector |
| `initial_position`               | `(0, -62000)`    | 初始位置（米）。不要通过拖节点位置设置起点                | Inspector |
| `initial_velocity`               | `(655, 0)`       | 初始速度（m/s），同时决定初始航向                   | Inspector |
| `dry_mass`                       | `8000.0`         | 飞船干质量（kg），不含燃料；没有货舱质量                    | Inspector |
| `fuel_capacity`                  | `6000.0`         | 燃料舱容量（kg），燃料不计入推进质量                  | Inspector |
| `initial_fuel`                   | `3200.0`         | 初始燃料（kg），重置航行恢复；成功离港自动补满有效容量              | Inspector |
| `orbit_radius_tolerance`         | `0.25`           | 稳定绕行半径波动容差（±25%）                     | Inspector |
| `orbit_speed_tolerance`          | `0.25`           | 稳定绕行速度波动容差                           | Inspector |
| `orbit_perturbation_tolerance`   | `0.2`            | 允许其他行星引力扰动上限（相对主导引力）                 | Inspector |
| `max_acceleration`               | `10.0`           | 额定加速（m/s²），加力喷口可增加 5           | Inspector |
| `max_deceleration`               | `10.0`           | 额定减速（m/s²），加力喷口可增加 5                         | Inspector |
| `propulsion_fuel_per_delta_v`    | `8000/3700≈2.16` | 每 m/s Δv 耗油（kg/(m/s)），不再按载重修正 | Inspector |
| `orbit_search_radius`            | `250000.0`       | 入轨选星搜索半径（米）                          | Inspector |
| `orbit_plan_horizon`             | `900.0`          | 入轨机动规划时限（模拟秒）                        | Inspector |
| `orbit_capture_tolerance`        | `0.04`           | 入轨捕获后速度/圆轨道速度允许偏差比例                  | Inspector |
| `max_steering_acceleration`      | `10.0`           | 额定方向推进加速度（m/s²），加力喷口可增加 5                    | Inspector |
| `capture_net_launch_speed`       | `60.0`           | 捕捉网相对飞船的发射速度（m/s），沿瞄准箭头方向叠加飞船速度；`0` 表示随飞船速度原地铺开 | Inspector |
| `camera_always_follow`           | `false`          | 视角始终跟随：近域与星图都以飞船居中（星图仍用全局拟合缩放）；WASD 不解除跟随，重置/切船保持锚点 | Inspector |

**核心计算**：

| 方法                                            | 公式/含义                                      |
| --------------------------------------------- | ------------------------------------------ |
| `get_total_mass()`                            | `dry_mass`（燃料不计重，无货重）             |
| `get_effective_acceleration()`                | `max_acceleration + 喷口加成`          |
| `get_effective_deceleration()`                | `max_deceleration + 喷口加成`          |
| `get_effective_steering_acceleration()`       | `max_steering_acceleration + 喷口加成` |
| `get_effective_propulsion_fuel_per_delta_v()` | `propulsion_fuel_per_delta_v`        |
| `fuel_to_delta_v(fuel_kg)`                    | `燃料 / 单位Δv耗油`，即油箱可提供的推进速度变化预算                |
| `capture_net_count()`                         | 统计 `upgrade_slots` 中 `capture_net` 的数量，决定快捷栏启用几格 |

**改装槽**：`upgrade_slots = ["", "", "", ""]`，4 个槽位，`shield_ready` 表示护盾是否可用。除捕捉网外，同一种改装只能安装一次；捕捉网允许占用多个槽位，每多一张对应船载装置栏多启用一格。改装效果见 §7.2。

## 5. 导航系统

### 5.1 `scripts/navigation/navigation_camera.gd`（extends Camera2D）

**职责**：WASD 平移 + 滚轮缩放世界画布；HUD 在独立 CanvasLayer 不受影响。

| 参数             | 默认值           | 作用                   | 修改方式      |
| -------------- | ------------- | -------------------- | --------- |
| `pan_speed`    | `600.0`       | WASD 平移速度（屏幕像素/秒）    | Inspector |
| `minimum_zoom` | `0.025`       | 最小缩放倍率               | Inspector |
| `maximum_zoom` | `4.0`         | 最大缩放倍率               | Inspector |
| `wheel_step`   | `1.15`        | 每格滚轮缩放步进             | Inspector |
| `ui_root`      | `../HUD/Root` | HUD 根路径，用于屏蔽 UI 上的滚轮 | Inspector |

**普通航行行为**：WASD 平移会解除跟随（`following=false`）；滚轮缩放**不会**解除跟随，跟随时由 `StarMapView._center_on_ship()` 保持船的屏幕锚点；自由视角滚轮固定光标下的世界坐标。

**飞船的「视角始终跟随」开关**：`ship.gd` 的 `camera_always_follow`。脚本默认值为 `false`，当前 `scenes/ships/ship.tscn` 已勾选为 `true`。开启后 `NavigationCamera.is_ship_follow_locked()` 为真，影响三处：

- `_pan()` 在**跟随状态下**直接返回——近域与星图里 WASD 都不会把视角拉成自由视角（关闭开关时星图仍可自由平移）；
- `reset_view()` 只复位缩放，`following` 保持为真，居中仍由 `StarMapView` 每帧维护；
- **星图模式照常进出，并且星图里同样跟随**：`M` 键、星图按钮、区域变化自动切图都正常；`set_map_mode(true)` 把 `camera.following` 设为开关值，`_fit_star_map()` 仍按全局范围算出拟合缩放，但 `_fit_bounds()` 在跟随时改为 `_center_on_ship()`——所以星图是「全局缩放下飞船始终居中」，不是「居中整个行星系统」。

关闭开关时行为与旧版一致：星图居中整个范围、可 WASD 平移，`F` 回船才跟随。`StarMapView._process()` 每帧在 `_observe_region()` 之后按开关把 `camera.following` 拉回 `true` 并居中，近域与星图都生效。教程视角锁（`lock_tutorial_view`）优先级更高，开启该开关也不影响教程的严格居中。该参数只是本船的视角偏好，不写存档。

**教程视角锁**：`TutorialController` 在活动步骤调用 `lock_tutorial_view(vessel, tutorial_zoom)`，固定近域视角并让教程船严格位于视口中心（不使用普通航行的右侧 HUD 避让偏置）。选船前跟随第一艘船，选船后跟随 `tutorial_ship`；模拟暂停和窗口 resize 时仍更新中心。控制器 Inspector 的 `tutorial_zoom` 默认 `2.0`，约将近域40像素船图显示为80像素，可调范围 `0.25～4.0`，只改显示不改物理。

锁定时 WASD、滚轮、M、星图按钮、区域变化自动切图与视图缩放适配均不能改变教学视角；普通 F 回船操作同样保持严格中心。教程结束、跳过、重置或恢复非教程存档时，通过 `clear_tutorial_view()` 清除目标并解除锁，恢复原视图模式；相机节点不接管模拟时间、物理或教程消息计时。

### 5.4 地图编辑器圆轨道速度建议

运行 `tools/map_editor.py`（需要带 Tk 的 Python；Windows 可用 `py tools/map_editor.py`）。选择小行星或太空垃圾，编辑并应用位置，在属性区下方选择参考行星与顺/逆时针，点击“计算建议”，核对速度和扰动后点击“应用建议初速度”，最后保存地图。只修改 `initial_velocity`，不移动对象、不改变质量。计算后若位置、行星参数、参考行星或方向变化，应用时会拒绝过期建议，须重新计算。

- `scripts/navigation/circular_velocity_advisor.gd` 调用所选行星真实的 `acceleration_at(point)`，取 `a_radial = -a.dot(r_hat)`，按 `v = sqrt(r * a_radial)` 生成切向速度；覆盖恒强层及其外平方反比层，不另造 GM 公式。Y 向下，因此 `(-r_hat.y, r_hat.x)` 为顺时针方向。当前行星固定，参考系速度为零；若行星实现 `flight_velocity`，模块会将其加到相对圆轨道速度上。
- `tools/circular_velocity_cli.gd` 是 headless 桥接入口。Tk 导出临时 JSON，交给真实 `map_loader.gd` 校验并实例化行星/城市后调用建议模块。通过 `GODOT_EXECUTABLE`、PATH 或项目旁 Godot 安装目录寻找引擎；未找到时提示配置，绝不回退到不匹配的近似公式。
- 行星中心、表面及内部、最大引力范围外、零/无效向心场均拒绝。最大引力边界按游戏规则包含，但离散积分可能越界，建议将轨道放在边界以内并留余量。
- 这是**单行星当前位置的瞬时建议**，不是多引力源稳定轨道求解器。面板显示当前位置其它有效行星/城市数量和合力扰动比 `|a_other| / a_radial`；多源不改变建议公式，即使当前扰动为零，整圈仍可能进入其它引力区。游戏积分误差也可能产生轻微径向波动。
- Godot 场景的危险区域、碎片、信息面板仍为编辑器可见节点；现有独立 Tk 地图编辑器沿用其控件结构，不引入集中脚本绘制的游戏 UI。

专项回归：`tests/circular_velocity_test.gd`（真实加速度、方向、拒绝条件、参考系、多源提示与游戏积分器整圈）；`tests/map_editor_orbit_test.py`（真实 CLI、JSON、Tk 计算/应用及过期建议拒绝）。

### 5.5 `scripts/navigation/map_loader.gd`（RefCounted，静态方法）

| 常量                 | 默认值                           | 作用        |
| ------------------ | ----------------------------- | --------- |
| `MAP_PATH`         | `user://space_map_v1.json`    | 用户自定义地图路径 |
| `BUILTIN_MAP_PATH` | `res://maps/default_map.json` | 打包内置地图    |

`load_map(allow_builtin)` 优先 `user://` 地图，仅不存在且允许时回退内置地图；用户地图存在但无效时返回错误，不静默覆盖。`apply_map(game, map)` 按地图 JSON 重建世界节点。

**地图对外的两个绑定**都写在根节点 / 对象字段里，游戏启动时硬校验，不合格直接判地图无效：对象用 `fields.interaction_data_path` 指向 `res://data/planets/*.json`（事件/人物/委托），地图用根节点 `cg_data_path` 指向 `res://data/cg/*.json`（地图专属 CG）。`valid_cg_path()` 只放行 `res://data/cg/` 下的直属 JSON，`read_map()` 的返回值因此包含 `objects` / `ship` / `cg_data_path` / `hash` 四项；`main._set_current_map(path, cg_path)` 把这两个路径同步给 `CgController` 与存档指纹。

运行时统一通过 `main.load_map_file(path)` / `main.load_world_map()` 替换地图：先读取并完整校验，成功后调用 `PortController.leave_port()` 恢复旧港口保存的世界/HUD可见性及相机等处理模式、清空停靠船引用，再执行 `apply_map` 与同步注册。读取失败返回 `false` 并保留原地图、港口与停靠状态；世界地图不存在或无效也视为失败，不能把旧地图当作加载成功。

### 5.6 行星 / 太空城事件与委托编辑器（`tools/quest_editor.py`）

运行 `python tools/quest_editor.py`（需要带 Tk 的 Python；Windows 上如果 PATH 里的 `python` 没装 tkinter，用 `D:\Coding\python\python.exe tools\quest_editor.py`）。单文件、仅标准库，与 `map_editor.py` 同一套结构：顶栏 + 左侧列表 + 右侧表单 + 底部状态栏、确认丢弃未保存修改、临时文件原子写入。

**操作是强制的三步**：① 打开地图 JSON → ② 左侧选中 planet/city 对象 → ③ 编辑「事件 / 人物 / 委托」。没打开地图前，页签、列表与保存按钮全部禁用。这样设计是因为地图是唯一知道「有哪些行星、它们的事件数据指向哪里」的来源，脱离地图配出来的文件不会有任何对象引用它。

- **只改地图的一个字段**：`fields.interaction_data_path`。「创建事件 JSON / 选择已有 JSON / 复制为新文件」三个动作会把 `res://data/planets/<名字>.json` 写回地图对象并标记地图为脏，「保存全部」时按打开时的路径写回；纯编辑事件内容不会重写地图，避免无意义的格式变动与 `map_hash` 变化。
- **创建事件 JSON** 时写入 `{"schema_version":1,"planet_id":<文件名>,"name":<对象 display_name>,"events":[],"diplomacy":{"persons":[]}}`，默认文件名 `<对象 id>.json`；「复制为新文件」用于拆开「多个对象共用同一份数据」的情况。
- **校验与运行时同源**：`validate_map` 复刻 `map_loader.read_map` 的字段白名单与数值范围；`collect_planet_errors` 复刻 `port_session._validate_planet` / `_validate_person_extras`，并追加静态交叉校验——`arrive_target` 与 `dock_city` 的 `target` 必须存在于当前地图，`talk_to_person` 的 `target` 必须是**项目里任意行星上存在的人物**（`person_registry()` 把 `data/planets/*.json` 全扫一遍，当前文件优先用编辑器内存里未保存的版本）；人物 id **允许跨行星重名**，用 `target_planet_id` 指明是哪颗星上的那个人（填了就必须真在那颗星上），委托 `id` 全项目唯一（`quest_registry()` 扫全部 `data/planets/*.json`——运行期任务表只按 id 建键，跨文件撞名会让另一颗星的同 id 委托直接显示成「已接取」）。保存前一次性列出全部错误，不是只报第一条。
- **人物下拉**：`talk_to_person` 的目标下拉列出全项目人物，标签是 `名字（planet_id）· 人物id`——用唯一的 `planet_id` 而不是可能重复的显示名做锚点，选中后写回 `target` + `target_planet_id`（`target_name` / `target_planet` 供清单提示）。历史上的裸 id 数据打开时按「当前行星优先」解析成标签，不会显示成 `person_1`。
- **命令行**：`--check [地图路径...]`（缺省检查 `maps/*.json`）校验地图及其引用的每份事件 JSON 与地图绑定的 CG，逐行输出并返回退出码 0/1，可挂进提交前检查；`--selftest` 用隐藏窗口跑一遍载入、选中与保存往返。两者都不写项目内真实数据。
- **CG 页（地图级）**：第四个页签不依赖左侧选中对象，只要求已载入地图。「创建 CG 配置」在 `data/cg/` 生成 `<地图名>.json`（内容 `{"version":1,"map":<地图名>,"cgs":[]}`）并把 `res://data/cg/...` 写进地图根节点 `cg_data_path`；表单覆盖 `id / image / text / duration / once / skippable / enabled / trigger`，四种触发条件按类型联动 `map`、`object + kind`、`quest`、`position + radius_m`。`collect_cg_errors` 与 `cg_controller.collect_errors` 同源，并追加地图交叉校验（`enter_object` 必须是本图对象、`map_enter` 必须是本图或 `*`）；图片缺失、委托 id 不在本图事件数据里只算提示。保存时 CG 文件与地图绑定一起落盘，纯改事件内容不会重写地图。
- **不做**：画地图、改对象坐标 / 半径 / 引力（那是 `map_editor.py` 的职责）；也不改 `data/planets/*.json`、`data/cg/*.json` 之外的任何数据。

数据投放位置、字段表、校验规则与常见故障见 **`docs/地图与事件数据导入指南.md`**。专项回归：`tests/quest_editor_test.py`。

### 6.5 序列帧纹理样式（`scripts/world/texture_style.gd`）

行星、小行星和太空碎片的外观统一由 `texture_id` 索引到 `TextureStyle` 注册表，由脚本或地图数据切换，不依赖每帧换贴图。

| 类别 | `texture_id` | 名称 | 图集 |
| --- | --- | --- | --- |
| `planet` | 0 / 1 | 罗宋 / 拉丁 | `assets/world/planet_russian_sheet.png`、`planet_latin_sheet.png` |
| `asteroid` | 0 / 1 / -1 | 沙漠（默认） / 铁锈 / 沿用静态外观 | `assets/world/asteroid_desert_sheet.png`、`asteroid_rust_sheet.png` |
| `debris` | 0 / 1 | 晶体 / 黑曜石 | `assets/world/debris_crystal_sheet.png`、`debris_obsidian_sheet.png` |

图集统一为 **6 列 × 6 行、36 帧**，由 `tools/build_texture_sheets.py` 从 `D:/user/window/<素材>/frames/0001.png…0036.png` 按文件名数字顺序生成。全部帧共用同一个正方形裁切框，保证逐帧不抖动；裁切框有两种定位方式：

- `bbox`（碎片、沙漠小行星）：取整段序列 alpha 并集的包围盒居中。
- `disc`（行星、铁锈小行星）：按**实心主体**的圆心与半径居中。行星帧里还有环、卫星轨迹和星点，铁锈岩石周围也有细小碎屑，它们在帧内位置不固定，若按 alpha 并集裁切，包围盒会被拉偏——圆盘（岩石）就会整体偏离帧中心（行星实测偏下约 13px、偏右约 6px，游戏中表现为球体与碰撞圈不同心；铁锈则会把岩石压小且偏心）。`disc` 模式用每行/每列「最长连续不透明段」识别实心主体，环、碎屑属独立短段不参与计算，因此圆心即帧中心。运行脚本会打印实测的 `disc_ratio`，行星直接填入样式表；小行星靠 `margin` 控制主体占帧比例（铁锈取 1.25，使主体等效直径约占帧宽 0.73，与沙漠那颗一致）。

新增一套外观只需两步：在 `JOBS` 里加一条生成任务（行星用 `center="disc"`、`margin=1.18`），再把 `TextureStyle.STYLES` 里对应分类加一个 ID。罗宋与拉丁共用同一裁切画幅，因此两套行星的 `disc_ratio` 都是 `0.8477`；`texture_id` 上界 8 由导出参数与地图校验共同约束。

播放方式：`Sprite2D` 的 `hframes/vframes` 设为 6×6，`frame` 由 `TextureStyle.frame_at()` 按累计时间与相位求值；每个碎片使用不同相位（`i * 5`），因此整团垃圾不会同步摆动。帧率由样式表的 `fps` 决定（碎片/小行星 12、行星 10）。

行星额外用 `disc_ratio` 补偿：图集帧里圆盘占帧边长约 `84.77%`，`planet_surface_scale()` 会换算 `Sprite2D.scale`，使圆盘视觉直径仍等于 `2 × radius_m`，与碰撞半径一致。`Surface` 保持 `centered`、`position`/`offset` 为 0，对齐只能靠图集裁切保证，不能靠挪动 Sprite2D。

地图字段：`texture_id` 已加入 `map_loader.gd` 的白名单与整数校验（`-1～8`），地图编辑器同步提供「纹理ID」项。它属于纯视觉字段，`_hash_source()` 在计算地图指纹时会剔除，因此只改外观不会让旧存档失效。修改样式后无需重新导入资源，图集在编辑器扫描时自动导入。

相关回归：`tests/texture_style_test.gd`（图集完整性、纹理切换、帧推进、行星圆盘补偿、**图集像素级校验**、地图字段与指纹）。像素级校验会从图集里实测圆盘圆心与直径占比：单帧偏移 ≤10px、六帧平均偏移 ≤5px（横向）/4px（纵向）、占比与注册值误差 ≤0.04，因此裁切偏心或改错 `disc_ratio` 都会直接失败。

## 7. 港口系统

### 7.1 分层结构

```
PortController (适配层，extends CanvasLayer)
    ├─ PortSession (会话模型，RefCounted)：共享信用点/事件/人物/改装校验
    └─ PortView (UI 渲染)：只读快照，发信号，不算业务
```

**数据流**：进入港口 → `enter_port()` 打开行星 JSON → 状态变化经 `PortSession` 计算 → `PortController._get_state()` 汇总快照 → `PortView.render()` 渲染。

### 7.2 `scripts/ports/port_session.gd`（纯数据模型）

**关键参数/常量**：

| 参数            | 默认值                            | 作用        | 修改方式 |
| ------------- | ------------------------------ | --------- | ---- |
| `PLAYER_PATH` | `res://data/player_start.json` | 玩家初始配置    | 改常量  |
| `MAX_NUMBER`  | `1e12`                         | 信用点数值上限 | 改常量  |
| `UPGRADE_COST` | `100` | 安装改装和护盾重充的统一信用点消耗 | 改常量 |
| `UPGRADES`    | 见下                             | 船坞配件表     | 改字典  |

**配件表 `UPGRADES`**（每项含 `name`、`description`、`credits`，可选 `slots` 槽位过滤；不使用材料）：

| id | 名称 | 价格（信用点） | 效果 |
|---|---|---|---|
| `computer` | 航行电脑 Lv1 | 100 | 预演时间 +50%；选中碎片/小行星时可视化其未来轨迹 |
| `fuel` | 燃料仓 Lv1 | 100 | 燃料容量 +20% |
| `shield` | 霍普尔盾 Lv1 | 100 | 可防御一次太空垃圾；耗尽后原槽位重充同样为 100 |
| `thruster` | 加力喷口 Lv1 | 100 | 加速/减速/方向推进各 +5 m/s² |
| `capture_net` | 捕捉网 | 100 | 可重复安装；冻结时间选定方向后发射一张持续膨胀的灰色网，像橡皮擦一样按覆盖面积擦除太空碎片的质量，擦到的质量当场计入回收 |

`install_upgrade(vessel, slot, id, docked)` 在扣款前检查停靠和港口数据、槽位范围、槽位限制、空槽、同类重复以及余额。捕捉网允许同类多槽位（每槽一件），其余改装仍要求同类唯一。护盾耗尽时允许在原护盾槽位重充，已可用的护盾不能重复付费重充；任何失败均不扣款。

**共享信用点 API**：

| 方法 | 含义 |
|---|---|
| `get_credits()` | 读取整支舰队共享余额 |
| `set_credits(amount)` | 设置非负整数余额，供存档恢复使用 |
| `add_credits(amount)` | 增减整数信用点；最终余额须在 0 到 `MAX_NUMBER` 内 |
| `reset_session()` | 恢复玩家初始余额并清空港口缓存与选择 |
| `get_state()` | 返回事件、人物、当前标签与余额快照 |

**玩家初始配置**（`data/player_start.json`）：`schema_version=1`、说明文字以及 `credits=1200`。不再定义货舱、商品质量或生活费。

**行星港口 JSON 结构**（`data/planets/*.json`）：`schema_version`、`planet_id`、`name`、`events`（事件列表）、`diplomacy.persons`（人物列表）。人物条目可带 `position`（归一化二维坐标，当前仅作数据保留，UI 不再按坐标布局）与 `quests`（可领取委托列表，见 §15）。文件中已不含 `diplomacy.relations`。

### 7.3 `scripts/ports/port_controller.gd`（适配层）

负责场景生命周期（进入时隐藏世界与航行 HUD，离开时恢复）、信号转发、汇总停靠船改装状态。`shipyard_slot` 记录当前选中槽位；仅城市停靠提供船坞。`refresh()` 重绘已打开的港口，供调试加款调用。`can_depart(vessel)` 只检查有效船、已停靠状态及活动港口中的船匹配，不进行费用结算；实际离港合法性仍由 `main._depart()` 校验，成功后补满燃料。

### 7.4 `scripts/ports/port_view.gd`（UI 渲染）

## 8. 进度系统（任务与教程）

### 操作目标达标立即解锁确认（2026-11-02）

- 选船、城市真实加速至20m/s、减速停稳，以及行星加速、稳定轨道、实际入轨目标达成后，当前对应消息立即填满进度并启用“确认继续”，不再等待原定阅读时长；仍须玩家点击后才结束消息或推进步骤。原有达标收油、教学暂停、输入锁和单阶段跳过保持不变。
- `DialogueWindow.complete_current_reading(token_key, token)` 仅接受匹配当前城市/行星教程token且需要确认的消息：`SLIDING_IN` 和 `READING` 立即完整展开并进入 `WAITING_CONFIRM`，已等待确认时重复调用幂等；`IDLE`、`SLIDING_OUT`、过期token、另一教程及普通自动消息拒绝。接口不发 `dialogue_finished`、不清队列、不自动确认。

- 恢复 `objective_done` 存档时，重新显示的当前操作消息同样立即可确认；惯性、燃料、方向介绍及完成文案等纯说明仍按自己的时长读条并逐条确认，下一步不能继承上一操作结果。
- `tests/tutorial_confirmation_test.gd` 覆盖接口各阶段/token边界、真实选船/20m/s、泊船资格与同token补充队列、提前泊船及行星目标；`tests/tutorial_pause_test.gd` 将操作读条延长至180秒，使用真实鼠标推进/减速和轨道积分验证达标立即可确认及读档恢复，不依赖等待计时结束。

### 教学达标暂停与输入锁（2026-11-02）

- 城市加速至20m/s、减速至泊船速度阈值，以及行星操作目标达成后，控制器立即收油并调用 `set_tutorial_pause(true)`；若当前说明尚未确认，模拟保持冻结，确认后由下一步的 `paused` 配置决定是否恢复。
- 教学暂停期间禁止重新加速、油门、推力方向和方向锁预设，避免确认恢复后突然启动。普通玩家暂停期间原有推力预设行为不变；确认、当前阶段跳过和ESC仍可使用。
- 固定步模拟循环同时检查教学暂停；达标信号在一个子步内触发暂停后，不再执行同帧剩余子步，并清理积算时间。
- 教程保存/恢复保留达标等待状态与原暂停状态；取消、跳过和重置清理教学锁，避免下一操作步或自由游戏残留暂停。
- `tests/tutorial_pause_test.gd` 覆盖真实推进、输入封锁及暂停生命周期；`tests/tutorial_pause_review_test.gd` 独立验证大delta达标暂停、重复输入无隐藏推力、确认恢复和减速暂停。


### 教学弹窗确认与阶段跳过（2026-11-02）

- 两个教程入队消息时设置 `requires_confirmation=true`。`DialogueWindow` 的读条达到时长后进入 `WAITING_CONFIRM`，保持当前内容，确认按钮从禁用变为可用；手动点击后才滑出并发出 `dialogue_finished`。普通通知不设置该字段，仍自动结束。
- 确认按钮位于场景节点 `Root/Panel/Margin/Content/Message/Confirm`，使用鼠标 STOP 防止点击穿透；其他原有对话布局及立绘结构保持不变。每条消息单独读条与确认，同次点击不确认下一条。
- 城市与行星控制器分别锁存实际操作目标达成状态；选船、加速、减速、稳定轨道和入泊成功不会越过尚未确认的说明。城市真实正向推进达到 `20 m/s`、减速到 `<=0.1 m/s`，以及行星加速/稳定资格/实际入轨达标时，`_complete_objective()` 立即收油并调用 `set_tutorial_pause(true)`，冻结模拟等待本步确认；确认后 `_enter_step()` 仅按下一步的 `paused` 配置保持暂停或恢复，不阻断尚未完成的操作步骤。
- 教学暂停与普通暂停分开：`main.gd` 物理入口及固定步循环直接检查 `tutorial_pause`，达标时清空 `accumulator` 并停止后续飞船提交。教学暂停期间 `_start_thrust`、油门、方向与夹角锁入口拒绝写入，仪表只读，不能通过重复点击、滑条或输入框暗存推力；已入轨等待确认时起航入口也拒绝撤销达标结果。普通暂停仍允许预设方向/油门，保持原玩法；确认、单阶段跳过和 ESC 菜单不受阻断。
- 两个教程状态增量保存可选 `objective_done` 和 `previous_pause`（沿用状态版本1/存档版本3），达标读档重播当前说明并保留教学暂停，旧存档缺字段默认未达标；行星旧状态缺 `previous_pause` 时默认非普通暂停。暂停菜单内恢复/取消/跳过时由 `menu.was_paused` 保留进入教程前的暂停，菜单关闭不能绕过教学暂停；失效目标降级跳过亦先恢复原暂停基线。
- 共享跳过按钮仅由 `ProgressionManager` 订阅，入口按当前活动控制器执行一次：跳过行星进入城市，跳过城市进入世界；两个控制器不再各自订阅同一 pressed 信号。独立启动教程时也按实际活动控制器处理。
- 续档在恢复新消息前先取消旧活动教程，避免旧行星控制器清理共享对话队列时删掉城市续档消息。
- 回归：`tutorial_confirm_review_test.gd` 真实鼠标点击验证确认及阶段跳过；`tutorial_test.gd`、`orbit_tutorial_test.gd` 显式确认消息后继续原真实操作链路。

| `config_path` | `res://data/dialogue_tasks.json` | 任务配置 JSON |

### 8.2 `scripts/progression/tutorial_controller.gd`（独立教程状态机）

| 参数 | 默认值 | 作用 |
|---|---|---|
| `CONFIG_PATH` | `res://data/tutorial.json` | 教程 JSON（19 个细步骤，含港口界面介绍） |
| `TARGET_PATHS` | 见代码 | 高亮目标 id → 节点路径映射 |
| `duration_scale` | `1.0` | 教程消息时长缩放（测试用） |

**状态机**：`start_new_game()` → 按步骤 `paused` 控制模拟暂停 → 观察真实操作（选船、正向加速、减速、泊船）并等待本步骤消息手动确认 → `completed`/`skipped`。操作先达成时以 `_objective_done` 锁存、收油并暂停教学模拟，不清除或越过当前待确认消息；玩家确认后使用已达成结果继续，不要求重做操作。返港期间提前泊船由 `_docked` 记录，当前说明全部确认后不再直接进入完成说明，而是先进入**港口界面介绍段**（`port_events` → `port_people` → `port_shipyard` → `port_depart` 四条 `message`），逐条确认介绍事件页、人物页、船坞页与起航后，才显示完成说明；完成说明也须确认后才能切换世界地图。`_shortcut_step_index()` 让提前泊船的捷径跳转到 `port_` 段起点，而不是直接跳到 `complete`。`dock_ready` 排在当前泊船说明后逐条确认，不替换尚未确认的正文。高亮通过 `highlight_requested(target_id)` / `highlight_cleared` 信号预留接口，`resolve_highlight_target()` 返回真实节点（含 PortView 各页签与起航按钮）。

**启动失败与结束去重**：步骤配置为空，或没有飞船/找不到安全起点时，教程不进入 `active`。此时对话队列无人消费且会被下一阶段 `clear_queue()` 吞掉，因此不再入队，而是把原因写入 `game.flight_message` 并刷新 HUD，再由 `_finish(true, true)` **延迟一帧** 发出 `tutorial_finished`，让调用栈先返回、编排器随后照常推进阶段，玩家不会卡在本阶段。`_finish()` 以 `_finish_emitted` 保证一局只发一次结束信号；正常完成（`_advance()` 走到末尾）与主动跳过（`skip_tutorial()`）也走同一入口，避免完成与跳过重复推进。

**重置与泊船门控**：`cancel_for_reset()` 只做 `_cancel(true)` 清理，**不推进阶段**；`restart()` 先清理再重走 `start_new_game()`，供 `main.gd::_reset()` 在教程活动时调用，实现「重置 = 本阶段从头重做」。`allows_docking()` 在没有教程时返回 true；本教程活动时只有 `return_port` / `approach` / `dock` 三个入港阶段步骤返回 true（既有提前泊船流程），其余步骤不提供泊船资格，因此教程中途经过港口也不会出现泊船按钮、不会进港后被教程暂停困住。

**教程 JSON**（`data/tutorial.json`）：`steps` 数组，每项含 `id`/`kind`/`paused`/`target`/`goal`/`text`/`duration`；另有 `dock_ready`、`unavailable` 附加消息。`kind` 取值：`select`/`accelerate`/`brake`/`message`/`dock`/`complete`。末尾港口界面介绍四条 `port_events`/`port_people`/`port_shipyard`/`port_depart` 为 `message`，`target` 指向 PortView 的事件/人物/船坞页签与起航按钮，供高亮层定位。

### 8.3 `scripts/progression/orbit_tutorial_controller.gd`（行星入轨教程状态机）

| 参数 | 默认值 | 作用 |
|---|---|---|
| `CONFIG_PATH` | `res://data/orbit_tutorial.json` | 行星入轨教程 JSON |
| `ORBIT_RADIUS_FACTOR` | `1.8` | 起始轨道半径 = 行星半径 × 该倍数（位于恒强层外） |
| `INITIAL_SPEED_FACTOR` | `0.9` | 初始切向速度占圆轨道速度的比例（略低，需玩家补足） |
| `THRUST_TARGET_SPEED_FACTOR` | `0.95` | 加速步骤达标的速度占比 |
| `tutorial_zoom` | `0.85` | 行星教程相机缩放（比城市教程小，让轨道进入视野） |

**流程**：`observe`（暂停介绍轨道概念，确认后继续）→ `orbit_physics`（科普速度与轨道的关系：离行星越近所需环绕速度越快、越远越慢，速度不足下坠、过高逃逸）→ `thrust`（沿切向加速，速度达到圆轨道速度 95% 且说明确认后推进）→ `coast`（推进停止后稳定绕行，`stay_available` 通过且说明确认后推进）→ `confirm`（点击行星「确认入轨」，`voyage_finished` 且说明确认后推进）→ `completed`（完成说明确认后切城市教程）。速度、稳定资格或实际入轨先达成时同样锁存 `_objective_done` 并暂停模拟，等待本步手动确认；不会提前切换说明或丢失操作结果。运行中的 `thrust`/`coast`/`confirm` 步骤读档不再无条件固化为普通暂停。

相机锁定**行星**为视角中心（而非飞船），让绕行轨道进入视野。确认入轨后飞船 `voyage_finished`，物理步不再提交该船，故完成判定放在 `_process` 帧级检测。与城市教程共用 `TutorialHUD`、`DialogueWindow` 和高亮层。

行星教程同样具备 `_finish()` 去重与启动失败兜底（提示写入 `flight_message`、延迟发出 `orbit_tutorial_finished`）、`restart()`（重置时本阶段重做）与 `cancel_for_reset()`（只清理不推进）。行星教程期间 `allows_docking()` 恒为 false：不会出现城市泊船按钮，也不会在暂停期间进港。

### 8.4 `scripts/progression/progression_manager.gd`（新手教程编排器）

按顺序驱动三个阶段（行星先、城市后），两个教程都完成后才进入世界地图：

| 阶段 | 地图 | 教程 |
|---|---|---|
| `ORBIT` | `res://maps/plante_teach.json` | 行星入轨教程（`OrbitTutorialController`） |
| `CITY` | `res://maps/city_teach.json` | 城市入港教程（`TutorialController`） |
| `WORLD` | `user://space_map_v1.json` 或 `default_map.json` | 无（自由游戏） |

新游戏由 `SaveManager` 调用 `start_new_game()`，先进入行星入轨教程，完成后切入城市入港教程，最后进入世界地图；依次 `load_map_file()` 切换地图并启动对应教程，每阶段初始化完成后保存进度。教程 `orbit_tutorial_finished` / `tutorial_finished` 信号驱动阶段推进。ORBIT、CITY、WORLD 三个入口均检查地图加载返回值：失败时不推进阶段、不启动下一教程、不执行阶段保存；真实行星确认入轨和城市泊船打开的港口会在成功切图前关闭，因此下一教程可正常选船并显示航行树。读档时 `prepare_for_restore()` 按存档阶段重新加载对应地图并返回成功状态，失败保留原阶段且 `SaveManager.restore_snapshot()` 立即中止；`stage == NONE`（旧存档或直接调用教程）时保持当前地图不变。

共享 `TutorialHUD/Root/Panel/Margin/Content/Skip` 由编排器**唯一订阅** `pressed`，在回调入口使用 `if/elif` 选取当前活动教程：行星教学一次点击只进入城市教学，城市教学再点击才进入世界。两个控制器不再直接订阅共享按钮，避免行星同步启动城市后，同一次信号继续调用城市跳过造成连跳。按钮文案随活动阶段更新为“跳过行星教学”/“跳过城市教学”；主动跳过当前阶段会清理该阶段待确认消息。

**重置航行不再连锁跳过课程**：`main.gd::_reset()` 不再先后调用两个 `cancel_for_reset()`（旧实现会同步推进两层阶段、一次重置跳过城市与行星两课并写档）。`cancel_for_reset()` 现在只清理不推进，`_reset()` 在飞船/航行状态重置完成后判断：城市教程活动则 `restart()`，否则行星教程活动则 `restart()`，都不活动则不动教程。重置后 `progression.stage` 与地图都不变，玩家在本阶段从头重做当前课。

**教程与港口交互**：`main.gd::_can_dock_city()` 追加 `_tutorial_allows_docking()`（汇总两个控制器的 `allows_docking()`），教程未进入入港步骤时即使飞船停在泊船点也不显示泊船按钮；入港步骤（城市 `return_port`/`approach`/`dock`）仍照常出现。若玩家已在港口且 `tutorial_pause` 为真，`_depart()` 会写入提示“教程进行中，请先完成当前步骤，或用教程面板跳过本阶段。”并刷新 HUD，由 `port_controller` 回显为错误提示，而不是静默失败。

`tests/tutorial_robustness_test.gd` 使用隔离目录回归三条健壮性行为：注入空步骤后启动只发一次结束信号且 `active == false`、`flight_message` 有说明；行星教程进行中 `_reset()` 后阶段与 `map_hash` 不变并回到第 0 步；`brake` 步骤停在泊船点不提供泊船资格而 `dock` 步骤恢复；`tutorial_pause` 时 `_depart()` 给出提示且不离开港口。

### 9.0 面板底板（共享皮肤）

所有内容面板共用一套金属板九宫格底板，不再各自内嵌 `StyleBoxFlat` 当面板背景。

| 资源 | 用途 |
|---|---|
| `assets/ui/panel_plate.png` | 九宫格源图 240×240，四角斜切 40px，中间 160×160 是原图的划痕区 |
| `assets/ui/panel_plate_small.png` | 同一张图的 96×96 缩小版，斜切 16px，供矮面板使用 |
| `assets/ui/panel_plate.tres` | `StyleBoxTexture`，`texture_margin` = 40，内容边距 0 |
| `assets/ui/panel_plate_small.tres` | `texture_margin` = 16，内容边距 0 |
| `assets/ui/panel_plate_port.tres` / `panel_plate_pause.tres` | 同上，但内容边距分别固定为 20/18 与 40/32，给原本靠 StyleBox 自带内边距排版的面板（港口主题、暂停菜单） |

**引用方式**：场景里写 `theme_override_styles/panel = ExtResource("9_panel")`，指向上面某个 `.tres`。原来的 `StyleBoxFlat` 定义仍留在文件里但没有被引用——想回退只要把这一行改回 `SubResource("PanelStyle")`，不用重做颜色。

**大图/小图怎么选**：`texture_margin` 决定四角保留多少像素，也决定面板能有多小。斜切角 40px 要求面板宽度和高度都大于 80px；矮于约 100px 的条状面板（舰队栏 64px、瞄准面板 62px、物体信息 126px、教程面板 100px）用 `panel_plate_small`，否则斜角会把整块板吃成八边形。经验线：短边 ≥ 200 用大图，否则用小图。

**配色**：底板整体是中性深灰（`#4E5156`，取自原图），所以原本配浅底深字的界面必须同步改字色——`flight_panel` 的 `PanelTheme` Label、港口主题（`port_theme.tres` 的 `Label` / `Button` / `LineEdit`）、`quest_offer` 的次要文字、`shipyard_detail_panel` 的正文都改成了 0.85~0.9 的浅灰；港口背景（`port_view.tscn` 的 `Background`）也从浅灰白改成深色，否则深板浮在亮背景上会割裂。港口按钮顺带从浅色圆角改成了深灰 + 1px 亮边的方角，圆角 8→4。

**纹理来源**：原图是一张 1600×1000 的 RGBA 面板，有效区域 44,44–1556,956（斜切角 30px），按九宫格裁角、取边、取中心拼成 240×240。中心块特意取的是原图中划痕最密的一块区域（相对主体左上角 60,140），否则大面板中间会是一片死板的纯色。

### 9.1 `scripts/ui/dialogue_window.gd`（对话通知，extends CanvasLayer）

| 参数 | 默认值 | 作用 | 修改方式 |
|---|---|---|---|
| `slide_seconds` | `0.25` | 滑入/滑出动画时长（秒） | Inspector |
| `minimum_read_seconds` | `0.2` | 读条开始后至少经过这么久才允许单击跳过（防误触） | Inspector |
| `screen_margin` | `(16, 76)` | 屏幕边距（x 水平、y 底部），`y` 决定距底高度 | Inspector |

**状态机**：普通通知仍为 `IDLE → SLIDING_IN → READING → SLIDING_OUT`；教程为 `IDLE → SLIDING_IN → READING → WAITING_CONFIRM → SLIDING_OUT`，用 `Time.get_ticks_usec()` 单调现实时间计时（不受模拟倍率/暂停影响）。FIFO 队列，`enqueue_dialogue(data)` 入队。数据字段：`portrait`（图片路径）、`text`、`duration`（现实秒）、可选 `requires_confirmation`（默认 `false`）。两份教程控制器入队时统一注入 `requires_confirmation=true`，涵盖 JSON 主步骤、泊船提示和异常提示；普通任务 JSON 不注入此字段，保持原自动结束行为。

**单击跳过读条**：`READING` 阶段单击（左键或空格/回车）立即结束当前读条——把进度条拉到满，带确认的消息进入 `WAITING_CONFIRM`（出现「确认继续」），不带确认的直接 `SLIDING_OUT` 进入下一条。跳过由 `_input` 捕获，读条期间吞掉输入防止穿透到航行操作；`elapsed < minimum_read_seconds` 时忽略点击，避免弹出瞬间的误触把整条对话吃掉。`WAITING_CONFIRM` 阶段不吞点击、仍由「确认继续」按钮处理（同次点击不确认下一条）。

**面板几何**：`_place_panel()` 以视口为基准计算——宽 `55%`、高 `100`、底边距 `76`、水平居中。`DialogueWindow/Root` 必须是整窗锚点（四个 offset 全 0），否则面板会整体偏移（历史 bug：`Root` 带了 `(-87, 7)` 偏移）。底部这块 `76..176` 的对话带由 `ThrustDial` 让出：仪表盘锚点改为 `offset_top=-444 / offset_bottom=-176`（`main.tscn` 与 `star_map_demo.tscn` 两处都要改），保证窄窗口下 55% 居中的对话条不与仪表、右侧信息面板相交。

`Root/Panel/Margin/Content/Message/Confirm` 是场景中已有的 `Button` 节点（不是运行时新建），编辑器内可见、默认禁用，运行时仅教程消息显示。每条消息计时期间禁用，读条结束后启用“确认继续”并保持弹窗；只有玩家点击后才滑出并发出 `dialogue_finished`，然后继续下一条消息。按钮使用 `MOUSE_FILTER_STOP` / `focus_mode=NONE`，阻止鼠标穿透航行或误用按键确认；其他非交互对话控件维持鼠标穿透。清队列、下一条消息和重复点击都会重置/检查按钮状态。

**尺寸修改**（见 `_place_panel()`）：
- 宽度 = 窗口宽 × `0.55`，高度 = `100.0`，底部居中，由 `screen_margin.y` 控制底边留白。
- 人物图是 `Root/Portrait` 独立节点，底部对齐面板并可向上伸出；大小由 `custom_minimum_size` 控制，`PortraitSpacer` 为正文预留横向空间，正文字号在 `Text` 节点 `font_size`。

### 9.6 `scripts/ui/space_object_info.gd`（物体信息面板）

点击太空垃圾/小行星显示类别与质量。`refresh(target, pixels_per_meter, zoom, trajectory_hint)` 由 `main.gd` 调用，第四个参数是可选的目标轨迹状态文案；`trajectory_hint` 为空时对应行不显示，面板高度恒定不跳动。

**航行电脑轨迹预测**（`main.gd` 内联，与玩家自身预演 `preview_job` 平行的独立 `target_preview_job`）：

- **门禁**：装有 `computer` 且选中碎片/小行星且处于近域视角，才建预测任务。门禁在数据层（`_target_preview_allowed`），未安装时连一次 `_integrate` 都不会跑。
- **一次算完整条**：复用 `_integrate`（与实飞同一积分器、同一 `SIM_STEP`），每帧推进 `TARGET_PREVIEW_STEPS_PER_FRAME` 步，算完后按屏幕像素抽稀、整段写入 `World/TargetPreview`（Line2D）。首点固定为选中时刻的 `target.flight_position`，积分点跨帧累积在 `target_preview_job.points` 里（而非每帧重建），保证多帧推进时轨迹起点不漂移；不在 `points` 上逐帧 append——`PackedVector2Array` 写时复制会退化成 O(n²)。
- **重算节流**：`TARGET_PREVIEW_TTL = 0.4` 秒；目标按预测折线前进，偏离或世界变化才重算。静止目标（`velocity²≈0` 或已在 `stopped_obstacles`）不画线，只出文字提示。
- **终点标记**：`World/TargetPreviewEnd` 下两个互斥子节点——普通预演结束画空心环（`Continue`），预测撞行星画红实心点（`Impact`）。标记 `scale = ONE/zoom.x` 保持屏幕恒定尺寸。
- **星图隐藏**：星图视角下船体预演本身不推进，目标轨迹同步隐藏（`_sync_visuals` 兜底门控）。
- **视觉规格**：线宽 `1.2 / zoom.x`（反向补偿相机缩放），颜色紫罗兰 `#A185F2`（α0.8）——与玩家琥珀色轨迹互补 180°，且不占用星图线青、速度箭头绿、坠毁红三个既有语义色。

回归：`tests/target_trajectory_test.gd`（未装电脑不预测、装上后产生轨迹、轨迹首点与目标位置一致、静止目标不画线只出提示、取消选中清空、星图隐藏、目标销毁清空、重置清空、信息面板文案）。

### 9.8 CG 剧情窗口与触发调度（`cg_window.gd` + `cg_controller.gd`）

`scenes/ui/cg_window.tscn`（`CanvasLayer`，`layer=45`）只包含**图片**与**文本**两部分，刻意去掉对话框的头像与确认按钮；`scripts/progression/cg_controller.gd` 读 `data/cg.json`，按条件把 CG 交给窗口播放。

**窗口状态机**：`IDLE → FADING_IN → HOLDING → FADING_OUT`，用 `Time.get_ticks_usec()` 单调现实时间计时，不乘模拟倍率。`enqueue_cg(data)` 是唯一入口，字段 `image` / `text` / `duration`（现实秒）/ 可选 `skippable`；FIFO 队列，先入队先播。淡入淡出时长由 `fade_seconds`（默认 0.35s）控制。点击左键、空格、回车、ESC 可提前结束（淡入期间和停留前 0.35 秒内忽略，避免误触），播放期间吞掉输入。

**暂停语义**：`cg_started` 时若模拟未暂停则置 `simulation_paused=true`，队列结束后只解除自己设的那次暂停；玩家原有暂停或 `tutorial_pause` 不会被覆盖。

**触发条件**（`trigger.type`）：

| 类型 | 必填字段 | 判定时机 |
|---|---|---|
| `map_enter` | `map`（地图文件名，`*` 任意） | `main.map_epoch` 变化，即每次成功应用地图 |
| `enter_object` | `object`（地图对象 id，`*` 任意）、可选 `kind` | `PortController.port_entered` 信号（行星入轨确认 / 太空城泊船） |
| `quest_complete` | `quest`（委托 id） | `QuestManager.quest_completed` 信号 |
| `reach_point` | `position`（米）、`radius_m` | 每 `poll_interval`（默认 0.1s）取受控飞船位置，用上一采样点到当前位置的线段与圆求交 |

`reach_point` 只在「圈外→圈内」触发一次，停在圆内不重复；线段求交保证高速穿过小圆也不漏判。`once` 默认 `true`，入队时即写入 `played`，中途存档或同帧多条命中都不会重播。

**地图标识**：`main.gd` 新增 `current_map_path` / `current_map_id` / `map_epoch`，由 `_set_current_map()` 在 `_ready` 加载、`load_map_file()`、`load_world_map()` 三处统一维护；`MapLoader.load_map()` 的返回值增加 `path`。`enter_object` 的对象 id 取自地图节点名 `Map_<id>`（`PortController._map_object_id()`）。

**持久化**：`CgController.make_state()` 把 `played` 写入存档 `cg_state`；`restore_state()` 恢复记录并同步 `map_epoch`、撤销读档瞬间误触发的播放；新游戏由 `ProgressionManager.start_new_game()` 调 `reset_for_new_game()` 清空，普通「重置航行」不清空。旧存档缺少该字段时按空记录处理，不读档失败。

**配置与校验**：`data/cg.json` 需要 `version=1` 与 `cgs` 数组；`collect_errors()` 校验 id 唯一性、`res://` 图片扩展名、文本长度、`duration>0` 以及各触发类型的必填字段，错误只 `push_warning` 并跳过该条，不会中断游戏。

**地图级 CG（与地图绑定）**：地图根节点可写 `cg_data_path`（只允许 `res://data/cg/` 下的直属 JSON，由 `MapLoader.valid_cg_path()` 硬校验，不合格整张地图判为无效）。`main._set_current_map(path, cg_path)` 在 `_ready` / `load_map_file()` / `load_world_map()` 三处同步记录到 `current_cg_path`；`CgController._sync_map_config()` 每次 `_process` 比对路径，变化时重新读取该文件并与全局 `data/cg.json` 合并。专属文件格式与全局一致，根节点可写 `map` 声明归属，与当前地图不符则整份忽略并告警；内部 id 会加上 `<地图名>/` 前缀，因此不同地图可以有同名 CG，存档按带前缀的 key 记账。换图时重置 `reach_point` 的采样点与圈内状态，避免跨地图位移误判。

完整字段表、绑定方式与故障对照见 **`docs/CG剧情配置指南.md`**；回归为 `tests/cg_test.gd`（含地图绑定、归属校验与前缀记账，已加入 `tools/run_regression.sh`）。

### 9.9 船载装置栏与捕捉网（`capture_net_panel.gd` + `capture_aim.gd` + `capture_net.gd`）

**瞄准层**：`scenes/ui/capture_aim.tscn` 是 `CanvasLayer`（`layer=9`，在 HUD 之下、世界之上），只包含从飞船中心出发的定长箭头与角度面板：

| 参数 | 默认值 | 作用 |
|---|---|---|
| `arrow_length_px` | `160` | 箭头长度（屏幕像素），不随相机缩放变化 |
| `arrow_color` | 浅灰白 | 箭头颜色 |
| `panel_offset` | `(56, -112)` | 角度面板相对飞船中心的偏移 |
| `panel_margin` | `12` | 面板与窗口边缘的最小距离 |

按捕捉网按钮时 `main._begin_capture_aim()`：记录当前暂停状态 → `simulation_paused=true` → 箭头初始角度取 `ship.heading.angle()`。拖动左键（`_unhandled_input` 中的鼠标按下/移动，落在角度面板上时不响应）或在该面板输入角度并回车，都会调用 `_set_capture_aim_angle()`；输入框在获得焦点期间不被外部覆盖。再次按同一按钮调用 `_launch_capture_net()`，按当时暂停前的状态恢复模拟；按 ESC、点暂停按钮、切换飞船、教程强制暂停、重置航行都会取消瞄准并隐藏箭头。

**网体**：`scenes/world/capture_net.tscn` + `scripts/world/capture_net.gd`，灰色半透明圆面 + 细边（`Polygon2D` + `Line2D`，半径 1 的单位圆按 `radius_m × 像素比例` 缩放，与太空垃圾同一套显示映射）。

| 参数 | 默认值 | 作用 |
|---|---|---|
| `initial_radius_m` | `80` | 发射瞬间半径（米） |
| `growth_rate_m_per_s` | `300` | 半径增长速率（米/模拟秒） |
| `max_radius_m` | `6000` | 半径上限；到达后**停止扩张但继续存在**，不回收 |
| `initial_mass_kg` | `120` | 网体自身质量（kg） |
| `lifetime_s` | `0` | 存活时长（模拟秒）；`0` = 永久存在，不自动回收 |
| `destroy_on_planet_impact` | `true` | 撞上行星是否销毁；关闭后网体穿过行星继续存在 |
| `erase_follow_rate_per_s` | `0.06` | 橡皮擦跟随速率（1/模拟秒），控制擦除逼近几何上限的快慢；`0` 表示瞬间擦掉 |
| `capture_efficiency` | `1.0` | 捕获效率：擦掉的质量中真正进网体的比例，`1.0` 表示擦多少得多少 |
| `capture_capacity_kg` | `2000` | 网体最大擦除质量（kg）；到顶后停止擦除，`0` 表示不设上限 |

发射速度来自飞船的 `capture_net_launch_speed`（默认 60 m/s），实际初速为 `飞船速度 + 箭头方向 × 发射速度`，因此网体不会瞬间落到飞船后方。这个值同时决定网体离开飞船的速度：调得过大（几百 m/s）网体会在几秒内飞出视野，看起来像“刚发射就没了”；设 0 则网体与飞船同速、原地铺开，适合当固定布网用。**网体是长时间存在的太空物体**：半径到上限只是停涨并提示一次「已扩张到最大半径」，只有撞上行星、或 `lifetime_s > 0` 且寿命耗尽时，才调用 `shutdown()` 并从 `main.capture_nets` 移除。网体不参与飞船碰撞，也不写入存档；重置航行或切换地图会清空。

**擦除模型（橡皮擦）**：网体不再“碰到整团就整团收走”，而是把整团太空垃圾当成一块可被擦掉的面积，`main._update_capture_nets(SIM_STEP)` 每步对每个接触到的 `space_debris` 执行：

1. **几何覆盖率** `space_debris.coverage_of(world_point, world_radius)`：擦头圆（网体）与整团圆（`current_radius_m()`）的交集面积 ÷ 整团面积，两圆相离为 0，小圆完全落在大圆内为 `min(R, r)² / R²`。它回答“这一网最多能擦掉多大比例”。
2. **历史峰值** `_erased_peak`：覆盖率取运行期最大值且单调不减——网体扫过一片就留下痕迹，来回移动不会把质量“擦回来”。
3. **质量指数逼近** `erase_towards()`：剩余比例向“1 − 峰值”确定的下限收缩，每步收缩 `1 − e^(−erase_follow_rate_per_s × step)`，所以擦除是渐进的而不是一步到位；返回值是本次剥离的质量（kg）。
4. **入账**：`main` 把剥离质量乘 `capture_efficiency` 交给 `net.absorb_erased()`，再受 `capture_capacity_kg` 截断；到顶时写一次「已达最大擦除质量」并停止对碎片做任何擦除。
5. **溃散**：剩余比例 ≤ 太空垃圾的 `scatter_threshold_ratio`（默认 `0.06`）时整团 `destroyed = true` 并隐藏。**这里禁止 `queue_free`**，节点要继续用于存档、重置与场景复用。

**碰撞半径随擦除收缩**：`remaining_mass_kg` 是唯一随擦除变化的物理量，`current_radius_m() = radius_m × sqrt(剩余比例)`，而地图配置的 `radius_m` 绝不改写（否则读档和检查器都会漂）。撞船扫掠（`main._swept_fraction`）、网体接触判定、选中环、信息面板与点击容差都读 `current_radius_m()`；`main._obstacle_radius()` 统一了“太空垃圾读当前半径、小行星读配置半径”。

**碎片视觉（真咬痕）**：`space_debris.tscn` 的 32 个 `Sprite2D` 各自持有一份 `ShaderMaterial`（`shaders/debris_erode.gdshader`），`uniform float erosion` 用两层不同密度的 UV 噪声 `discard` 像素并把剩下的部分压暗，做出边缘带锯齿的缺口，而不是整块突然消失。`erode_at()` 按碎片中心到擦头圆心的距离给 `_erosion[i]` 累加，覆盖边缘留 `0.12` 的起步量避免整片齐刷刷消失；`_erosion[i] >= 1` 时该碎片隐藏。

**为什么擦除”看不见”，以及现在怎么解决**：网体半径上限 6000 m 远大于整团的 1000~7000 m，`erode_at()` 早期用网半径做归一化分母（`1 - 距离 / reach`），于是整团所有碎片都落在网内、权重全接近 1，结果是**所有碎片同时溶解**，看起来像整团一起变淡，看不出从哪一侧被擦；同时危险区 `MapArea` 的缩放只跟 `radius_m`，质量掉到 88% 时半径只缩 6%，肉眼几乎无法分辨。现在的做法是三条一起生效：

1. **溶解权重按相对跨度**：分母改用 `span = max(current_radius_m(), reach) × 1.1`，越靠近网中心越快，网在左侧时左侧碎片先消失。
2. **碎片数量与质量对齐**：`_sync_fragment_erasure()` 按 `alive = round(数量 × 剩余比例)` 计算应剩几块，把离擦头最近的一批 `_erosion` 直接置 1 并隐藏，保证质量掉多少块就少多少块（只靠渐变值时网太大永远到不了 1）。
3. **危险区轮廓按方向凹陷**：`_prepare_map_area()` 先把 `Polygon2D` 的原始 16 顶点用**极坐标重采样**加密到 64 点（`_resample_rim`，对半径和角度分别插值；用线性插值的话弦中点比顶点短 1.9%，初始轮廓就已经不是正圆）。`_refresh_map_area_shape()` 每次按 `shrink = sqrt(剩余比例)` 整体收缩，再朝擦头方向啃缺口：`toward = 顶点方向 · 擦头方向`，`bite = clamp(已擦比例 × 2.6 × toward^1.6, 0, 0.85)`，该顶点半径 = `基准 × shrink × (1 − bite)`。正对擦头的一侧凹得最深、背面几乎不动。以 `radius_m = 1500` 为例：未擦除时最短/最长都是 `100`；读档到 87.9% 时缺口侧 `64.3`、对侧 `93.8`；擦到 77% 时缺口侧 `35.6`、对侧 `87.8`。`Outline`（`Line2D`）同步更新，避免只改填充导致描边错位。重绘会触发多边形重新三角化，20 倍速下每帧可跑 80 步，因此按剩余比例变化 `0.002` 节流。
4. **读档和重置同样保留缺口**：`_erase_direction` 默认 `Vector2(-1, 0)`，`restore_erasure()` 只清掉 `_has_erase_point`（没有真实擦头位置）而不清方向，所以读档后仍能看到被擦过的一侧。这一条是必须的——只靠 `sqrt(0.879)` 的整体收缩只有 4.2%，玩家在游戏里看到的就是一个“稍微小一点的圆”，会认为擦除根本没有生效。真实擦除时 `erode_at()` 用「擦头世界坐标 − 整团中心」更新方向。

实测（整团 `radius_m = 1500`、24 块碎片、擦头在左侧 0.8R 处）：剩余 88% 时碎片 21 块、擦头侧轮廓半径 81.6、对侧 94.2；剩余 73% 时碎片 18 块、两侧 58.9 / 87.0。擦除过程中质量每变化超过 1% 才重排一次布局（`_update_debris()`），既让碎片随整团收缩，又不在每个模拟步里空转。

**碎片布局的两个坑**：

- 碎片位置按配置的 `debris_count` 分摊（`sqrt((i + 0.5) / debris_count)`），不再按当前可见数量，所以擦除不会让剩余碎片外移。
- `minimum_fragment_pixels` 会被 `spread_limit` 钳制，`spread_limit = 100 / (半对角线 × (sqrt(数量) + 0.2) × 1.5)` 给出单块占位上限；否则大半径下像素下限会把碎片顶到放不下、`available_radius` 归零，32 个 Sprite 全叠在圆心白烧 32 层 overdraw。注意**只钳制像素下限**，米制尺寸 `debris_size_m` 不受影响（否则“改变危险半径不改变碎片显示尺寸”就不成立）。`_screen_scale` 必须写成 `get_viewport().get_screen_transform() × get_canvas_transform() × 自身 scale`：漏掉相机缩放会让碎片尺寸不对，把自身 scale 又算一次则会让下限失真。

**持久化**：存档 v4（`space_save_v1.dat`，`VERSION = 4`）在 `obstacles` 里为每团太空垃圾多写一个 `remaining_mass_kg`；`_read_save` 与 `_compatible` 的版本白名单都是 `[1, 3, 4]`，v3 及更早存档没有该字段时视为整团完好。读档调用 `restore_erasure(remaining)`：按剩余比例把外侧碎片直接判为已擦除（`keep = round(可见数量 × 比例)`），并把 `_erased_peak` 设为已擦比例，避免读档后同一片区域还能“再擦一遍”。

**界面反馈**：有网体在场时快捷栏标题变为「船载装置 · 网 N 张」（`render` 的 `status_text`），鼠标悬停显示提示框「捕捉网 N 张 · 已擦除 X kg · 擦空 M 片碎片」（`status_tip`），无网体时标题还原为「船载装置」。之所以写在标题而不是信息栏：`Info` 与快捷栏同属 `FlightPanel` 的同一个 VBox，多加一行会把快捷栏整体下推，窄窗口下容易与右侧推力仪表打架；标题又必须短，因为 `FlightPanel` 固定 320 宽，长串会溢出面板。擦除、到容量上限、半径到上限、回收、撞行星都会写入 `flight_message`。

### 9.10 回收结算（捕捉即回收）

**规则**：捕捉网擦掉多少质量，就当场回收多少质量。网只是擦头，不是容器——不需要把它开去行星，也不需要有第二件装备替它收货。

**记账点**在 `main._update_capture_nets()` 的擦除分支里：

```gdscript
var absorbed_before: float = net.absorbed_mass_kg
net.absorb_erased(erased_mass, wiped_fragments)
var gained: float = net.absorbed_mass_kg - absorbed_before
if gained > 0.0:
    _note_recovered(gained)
```

用“擦除前后的 `absorbed_mass_kg` 差值”而不是直接用 `erased_mass`：`absorb_erased()` 内部要乘 `capture_efficiency`、还要被 `capture_capacity_kg` 截断，只有差值才是真正进网、真正该记账的量。`_note_recovered()` 累加 `recovered_mass_kg` 并调用 `QuestManager.note_recycle(kg)`，`recycle_mass` 任务因此可以与擦除同步推进——玩家在碎片带里擦，任务进度就在涨。

**网体寿命与落点不复核结算**：撞行星（`_discard_capture_net()`）、寿命到期、重置航行都只销毁网体，**不动** `recovered_mass_kg`。这样不会出现同一批质量被算两次，也不会出现“网掉进行星才给钱”的延迟反馈。所以空网、满网、烧网的差别只体现在还能不能再擦，不影响已记的账。

**HUD**：快捷栏标题仍是「船载装置 · 网 N 张」，提示框在原有的「已擦除 X kg · 擦空 M 片碎片」之后多一行「已回收物资 X kg」。网不入存档，重置航行或切换地图时 `_clear_capture_nets()` 把网体与 `recovered_mass_kg` 一起清空。

> 设计沿革：这一节先后写过「拖网撞行星」「绞收回船」「锚定等引力收货」三版，都是围绕“网怎么把物资送到行星/飞船”做文章。结论是这件事不该存在——捕捉动作本身就是回收动作，运输环节纯属自找的。回收钩（`recycle_hook`）已整体下线，老存档里的该装备在 `save_manager._sanitize_slots()` 中读档时清空为空槽（`RETIRED_UPGRADES`），不会让存档判为损坏。

回归：`tests/capture_net_test.gd`（安装、快捷栏绑定与布局、瞄准暂停与角度、发射速度、半径增长、覆盖率、指数擦除速率、捕获效率入账、捕捉即回收记账、回收任务随擦除推进、持续擦除到溃散、容量上限、到期回收、网体销毁不重复结算、存档兼容、重置清理），已加入 `tools/run_regression.sh`。

### 9.11 装备目录、解锁与机库舰载机（`data/equipment.json` + `equipment_catalog.gd`）

**唯一数据源**：`data/equipment.json` 的 `equipment` 表是装备的全部静态数据——`name` / `description` / `credits` / `requires_unlock` / `stackable` / `values`。脚本里不再写死名称、价格与数值：`EquipmentCatalog`（`scripts/equipment/equipment_catalog.gd`，静态读取并缓存）提供 `entries()` / `values()` / `number()` / `unlockable()` 等查询，`port_session.UPGRADES` 也由它生成。JSON 损坏时回退到 5 件基础装备的内置定义并 `push_error`，游戏不会因为配置写错而起不来。

| 字段 | 作用 |
|---|---|
| `requires_unlock` | `true` 表示必须在船坞里由任务奖励解锁后才出现、才可安装 |
| `stackable` | 允许同一件装备重复占用多个槽位（目前只有捕捉网） |
| `credits` | 安装价格；护盾重充价用 `values.recharge_credits` |
| `values` | 全部可调数值。飞船侧读 `fuel_capacity_scale` / `acceleration_bonus` / `preview_seconds_scale` 等，捕捉网读 `launch_speed` / `radius` / `capacity`，机库读 `drones.*` |

**解锁链路**：委托 JSON 增加可选字段 `reward_unlock`（填装备 id，如 `hangar`）→ `QuestManager._settle_unlock()` 在完成时调用 `PortSession.unlock_equipment(id)` → `get_slot_upgrades()` 只返回已解锁装备，未解锁的连候选按钮都不出现 → `SaveManager` 的 `unlocked_equipment` 字段（存档版本 5）负责持久化。`PortSession.is_unlocked()` 对 `requires_unlock=false` 的装备恒为真，因此旧存档全体装备照常可用。

**任务编辑器**：`tools/quest_editor.py` 启动时直接读同一份 JSON 生成装备下拉与 `reward_unlock` 校验（`UNLOCKABLE_UPGRADES`），新增可解锁装备只改 JSON，不用再同步两份清单。编辑器写入时选「（不解锁装备）」会彻底删掉该字段。

**机库与舰载机**：`hangar` 装上后 `ship.skill_loadout()` 把它展开成 `drone_engineer` / `drone_guard` 两格快捷栏（机库自身不占按钮，`main._on_skill_slot_pressed()` 按 `drone_*` 分派）。两种舰载机都是 `scenes/world/drone.tscn` 实例，挂在 `World` 下，推进走 `main._integrate()` 同一个积分器，不新增物理循环：

- **工程机**：`_can_release_drone()` 要求 `_is_in_gravity_region()`，释放即按 `_circular_velocity_at()` 进入该半径的圆轨道（行星引力是「恒强层内 g 恒定、层外按平方衰减」，所以圆速度分两段算，不能直接套 `sqrt(mu/r)`）。每步对 `recycle_radius_m` 内的碎片做 `erase_towards()`，回收质量计入 `recovered_mass_kg` 与 `recycle_mass` 任务；仓容或寿命用尽自动回收。
- **近卫机**：贴在母船前方 `offset_m` 处跟随，每步对 `cone_angle_deg` / `range_m` 扇形内的碎片调用 `space_debris.melt_mass()` 直接扣质量（按 `melt_kg_per_s` × 步长），擦空后碎片坍缩。它**不计入回收物资**——是摧毁不是打捞。
- 同一机型同时只允许一架，再点一次即召回；换图、重置航行、母船损毁都会清空在轨机。舰载机不入存档，只在本次航行内有效（与捕捉网一致）。

回归：`tests/equipment_unlock_test.gd`（目录读取、未解锁不可安装、任务奖励解锁、机库展开两格、引力区限制、工程机圆轨道与回收、近卫机扇形清除、存档往返）。

**装完看不出来怎么办**：机库本身不占快捷栏，装完在船坞里除了槽位文字没有任何变化，很容易被当成"没生效"。所以安装成功时 `PortController._install_notice()` 会点名解锁的「工程机 / 近卫机，起航后可用」，槽位标签也补一行「工程机 · 近卫机」。飞行中工程机在引力区外是禁用态，而 Godot 不会给禁用按钮弹 tooltip，所以按钮文案直接写成「工程机 / 需引力区」。

**拆除装备**：船坞选中槽位后点「拆除槽位 N」（`port_view.gd` 的 `%RemoveButton` → `upgrade_remove_requested` → `PortController._remove_upgrade()`）。

| 规则 | 说明 |
|---|---|
| 费用 | 免费，**不返还信用点**；空槽位按钮直接禁用，`PortSession.remove_upgrade()` 也会拒绝 |
| 停泊限制 | 必须在城市船坞（`shipyard_available`）内，未停泊一律拒绝 |
| 护盾 | 槽位清空的同时 `shield_ready = false`，不会留下"盾没了还能挡一次"的残留 |
| 燃料仓 | 调 `ship.clamp_fuel_to_capacity()` 把多余燃料排掉；否则会出现 `fuel > get_fuel_capacity()`，读档校验会判成存档损坏 |
| 捕捉网 | 正在瞄准时立即 `_cancel_capture_aim()`；**已发射的网是独立物体，留在太空继续工作**（质量在进网那一刻已记账，不需要回收） |
| 机库 | `main._clear_drones()` 立刻回收全部在轨舰载机，快捷栏两格一起消失 |

## 10. 持久化（存档）

### `scripts/persistence/save_manager.gd`

| 常量 | 默认值 | 作用 |
|---|---|---|
| `SAVE_PATH` | `user://space_save_v1.dat` | 存档文件 |
| `TEMP_PATH` / `BACKUP_PATH` | `.tmp` / `.bak` | 临时与备份文件 |
| `GAME_SCENE` | `star_map_demo.tscn` | 游戏场景路径 |
| `VERSION` | `5` | 写入 v5，并兼容读取 v1/v3 |
| 自动保存间隔 | `30.0` 秒 | `_process` 中 `elapsed >= 30` 触发 |
| 关键节点存档 | 停泊 / 起航 | `main._save_checkpoint()` → `save_checkpoint()`，帧末写入并重置上面那个计时 |

**关键节点自动存档**：`main._confirm_arrival()`（行星停泊）、`_finish_city_arrival()`（城市停泊）、`_depart()`（起航）三处在状态改完后调用 `_save_checkpoint()`。它不直接抓快照，而是 `_save_checkpoint_now.call_deferred()` 推到帧末——教程阶段切换会在同一帧里 `load_map_file()` 重载地图（还会顺手 `leave_port()`），当场抓快照可能存下「阶段已经变了、地图还是旧的那张」的中间态，读档时 `map_hash` 对不上就判成损坏存档。帧末写入保证快照里的地图 hash 与 progression 阶段永远是同一份状态。

`SaveManager.save_checkpoint()` 复用 `save_game()` 的同一份文件，成功后把 `elapsed` 归零（否则停泊存档刚写完，下一帧就撞上 30 秒计时再写一次）；存档未启用（地图无效、没走主菜单的测试环境）或 `map_load_error` 为真时直接返回 `false` 不写盘——地图加载失败时 hash 指向的是一份没加载成功的地图，写下去等于毁档。失败时 `main` 把「自动存档失败，原存档已保留。」追加到 `flight_message`，不吞掉停泊/起航本身的消息。

需要单独触发时也可以直接调用：`SaveManager.save_checkpoint()` 返回是否写入成功。

回归：`tests/autosave_checkpoint_test.gd`（城市停泊写盘且记录停靠船、停泊存档把 30 秒计时归零、起航写盘且清空停靠记录、真实积分取得行星轨道资格后确认到达同样写盘、`map_load_error` 时拒写且原文件字节不变、停泊中的存档可恢复回港口），已加入 `tools/run_regression.sh`。

**「上次起航」回档点（撞毁 / 燃油耗尽）**：`main._depart()` 起航成功后调用 `_stash_departure()`，帧末执行 `SaveManager.stash_departure()`，用同一份 `make_snapshot()` 把整局状态（船况、信用点、装备解锁、改装槽、任务/教程/CG 进度、障碍物擦除进度）存成 `departure_snapshot`，**只放内存、不写盘**——重开游戏本来就等于读档，写盘反而会让新开一局回档到上一局的起航点，白丢进度。

回档入口只在**卡死**时露出（`main._rollback_reason()`）：`ship.crashed` 为真，或燃料耗尽（`fuel <= 0.0001`）且未入轨。判定「未入轨」用 `is_instance_valid(ship.orbit_source) and ship.stay_available`：已经站在可确认的稳定轨道上时还能入港补给，不算卡死，不给回档。`voyage_finished`（停泊中）与还有燃料时同样不提供。`HUD/Root/FlightPanel/Margin/Content/RollbackButton` 默认 `visible=false`，命中卡死才显示并把原因写进 `SelectionStatus`（「飞船已损毁 · 可回档到上次起航」/「燃料耗尽且未入轨 · 可回档到上次起航」）；没有起航记录时按钮置灰、文案改成「无起航记录」。

`SaveManager.restore_departure()` 套用与读档完全相同的 `restore_snapshot()`：先按快照里的 `progression_state` 阶段加载对应地图（所以教程中途换图后也能回档），再恢复全船/障碍物/信用点/`unlocked_equipment`/任务与教程状态。恢复期间 `enabled=false` 且 `set_physics_process(false)`，避免把中间态写进存档或让船多跑一帧。`main._rollback_to_departure()` 在调用前清掉不入存档的本次航行临时态：捕捉网与 `recovered_mass_kg`、在轨舰载机、捕捉网瞄准、查看面板、自动驾驶、入轨选星与预演。

回归：`tests/rollback_test.gd`（新局无回档点、起航记录回档点、撞毁时按钮可见可点且完整在窗口内、回档恢复位置/速度/燃料/信用点/装备解锁、脱困后按钮隐藏、燃油耗尽且未入轨才提供回档、已在稳定轨道或还有燃料或停泊中不提供、无回档点时点击不改状态只给提示），已加入 `tools/run_regression.sh`（隔离目录关键字 `space-rollback-regress`）。

**流程**：新游戏/继续游戏切换场景 → `_attach_after_scene_change` 拦截 → `restore_snapshot` 恢复 → `save_game` 写临时文件再原子替换。v4 保存飞船航行状态、改装槽与护盾状态、障碍物运动/销毁状态与太空垃圾擦除进度（`remaining_mass_kg`）、顶层共享 `credits`、选择/停靠、暂停/倍速、任务状态、城市教程状态（`tutorial_state`）以及教程编排状态（`progression_state`，含阶段与行星教程状态）；不保存货舱、港口库存、生活费账单或矿体消耗数据。恢复先按 `progression_state` 阶段加载对应地图，再 `session.reset_session()` + `session.set_credits(data.credits)`，不会额外补油。成功城市离港或行星轨道起航时才补满有效油箱容量，且不扣信用点。

继续使用原 `space_save_v1.dat` 文件路径以便发现旧存档。读取校验接受版本 1/3/5（`_read_save` 与 `_compatible` 两处白名单必须同步）；v1 中废弃的经济、采集、矿体消耗字段忽略，缺失的 `progression_state` 按阶段 `NONE` 处理（保持当前地图不变），缺失的 `remaining_mass_kg` 视为该团太空垃圾完好，仍按现行航行字段和地图 hash 校验；地图 hash 不一致时拒绝恢复。

## 14. 引力区外自动航行

选中可航行飞船且位于**所有行星和城市引力范围之外**时，推力仪表显示编辑器可见节点 `Layout/AutoPilot`（“自动驾驶”按钮）。点击先进入待命，再在近域或星图空白处右键设置导航点开始执行；执行中再次右键立即改目标，保留当前位置、速度和燃料，使用完整速度矢量闭环重新修向、制动和加速。到达回自动待命，取消回手动但保留惯性。无重力判断按每个源的几何范围，不以合力是否抵消为准。

### 14.1 状态字段（`scripts/ships/ship.gd`）

| 字段 | 含义 |
|---|---|
| `autopilot_enabled` | 自动模式：开启且 inactive 时为待命 |
| `autopilot_active` | 是否正在执行当前目标，到达后清除此态但保留 enabled |
| `autopilot_target` | 自动航行目标世界坐标（米），与左键导航参考点独立 |
| `autopilot_max_speed` | 最大期望速度，默认 500 m/s；输入必须有限，范围 1～100000 |
| `autopilot_phase` | 0 加速/修向 / 1 巡航 / 2 制动，仅作显示，每步可重新切换 |
| `autopilot_acceleration` | 本步真实付费推进加速度矢量，供橙针显示 |

`reset_flight()` 会复位以上字段。

### 14.2 推进与生命周期（`scripts/game/main.gd`）

- `_toggle_autopilot_mode()` 进入待命时清手动油门、长按推进和入轨指令；`_set_autopilot_target(point)` 是右键设点/换点唯一入口，仅自动模式且未暂停时接受有限、引力区外目标。普通暂停可冻结执行，右键不设点；教学暂停取消自动模式且拒绝输入。
- `_autopilot_integrate(...)` 由真实飞行和预览共用，保持原参数签名。令 `a=min(accel,decel)` 保守满足所有方向额定能力，制动包络 `v_env=sqrt((a*dt)²+2*a*distance)-a*dt` 对应 `v²/(2a)+v*dt<=distance`；期望速度取朝目标方向、模长 `min(max_speed,v_env,distance/dt)`。距目标 ≤0.1 m 时期望速度为零。
- 计算完整 `request=desired_velocity-current_velocity`，实际 `delta_v=request.limit_length(min(a*dt,fuel/coefficient))`，因此横向速度、反向初速和超限速均受有限推力修正；燃料只扣 `|delta_v|*coefficient`，位置只由既有 `_integrate` 推进，不吸附、不免费转向、不因无油清速度。到达须位置误差 ≤0.2 m 且速度 ≤1e-6 m/s；末段速度同样通过有限且计油的 Δv 归零。
- `_is_in_gravity_region()` 逐行星/城市调用 `contains_gravity_point`（含边界），即使合力抵消、弱引力或行星中心也不能启用。`_crosses_gravity_region()` 对线段与行星圆/城市旋转矩形扫掠，单步外→内→外也立即关闭；共享控制单步同时检查真实积分终点及本步预期路径。
- `_stop_autopilot(reason, vessel=null)` 清指定船 enabled/active、相位、目标和推进指令，绝不改位置、速度和燃料；默认当前船，避免多船时误清。进入引力、无油、损毁、停泊、切船、重置、切图、读档均清两态；到达仅清 active 回待命。自动驾驶意图不保存，`restore_snapshot` 清旧意图后恢复存档速度/燃料。
- 导航点标记 `World/AutopilotMarker` 仅执行中显示。预览使用同一矢量控制器及范围退出逻辑；到达后停在真实终点，耗油或进引力退出后继续预演惯性/引力，不伪造停船。推进信号 `source=autopilot`，不触发首次手动推进任务。

### 14.3 仪表样式（`scripts/ui/thrust_dial.gd` + `.tscn`）

`Layout/AutoPilot` 为场景内按钮（不是运行时生成），仅有效选中船且无引力/非教学暂停/非港口/非入轨选星/有燃料时显示。开启后隐藏手动控件，显示 Dial、最大速度、执行/待命提示与返回手动取消按钮。`sync_state()` 每帧从当前船 enabled/active 重建样式，避免清理后残留自动 UI；橙针显示实际 `autopilot_acceleration`，无出力时隐藏，绿针保持真实速度。最大速度通过 main 接口校验并刷新预览，SpinBox 限制为正值且点击框外失焦提交；方向和油门在待命/执行期间均禁用。

### 14.4 测试

`tests/autopilot_test.gd` 使用真实 `root.push_input` 点击场景按钮→待命→近域/星图右键设点，覆盖零速短程、非共线/反向初速、各相位改目标、限速与焦点提交、近点高速不得瞬停、每步推进/耗油边界、合力抵消与城市范围、高速扫过引力区、预览一致性、取消/暂停/教学/重置等生命周期。运行需 `--headless` 与路径含 `space-autopilot` 的隔离 APPDATA，不访问玩家存档。现有 `thrust_dial_test.gd` 与 `save_roundtrip_test.gd` 分别回归原手动仪表和存档恢复。

## 15. 任务（委托）系统

### 15.1 分层

```
data/planets/*.json  persons[].quests   ← 委托定义（数据）
QuestObjective（RefCounted 基类）        ← 单种判定规则
QuestManager（主场景根下 Node）           ← 接取/进度/完成/奖励
QuestList（HUD/Root 下 PanelContainer）   ← 只订阅信号，不反向读航行状态
```

`QuestManager` 每 0.25 秒自累计评估一次，不逐帧判定。任务状态只存在管理器里，`QuestList` 与港口 UI 都只读 `state()` / `active_quests()`。

### 15.2 任务字段

| 字段 | 说明 |
| --- | --- |
| `id` | 全局唯一，重复接取会被拒绝 |
| `title` / `description` | 清单与领取面板的显示文本 |
| `type` | 判定类型，必须在 `QuestManager.TYPES` 注册 |
| `count` | 需要达成的次数，缺省 1；清单据此显示进度条与 `x/y`。`recycle_mass` 的 `count` 会被目标质量覆盖（两者保持一致） |
| `reward_credits` | 完成时一次性加到舰队共享信用点 |
| `reward_unlock` | 可选。完成时解锁 `data/equipment.json` 里 `requires_unlock=true` 的装备（如 `hangar`）；填不可解锁的 id 只告警不生效，编辑器会直接拦下 |
| `requires_return` | 可选布尔。为 `true` 时目标达成只把委托推进到 `awaiting_return`（待复命），**不发奖励、不发 `quest_completed`**；玩家必须回到委托人处交谈（`note_talk`）才真正完成。缺省 `false`，行为与旧数据一致 |
| `return_line` | 可选。复命时补播的一句台词（说话人是委托人）。留空则用默认台词 `「委托人名字」的事，办妥了？` |
| `target` | 目标 id：`arrive_target` 填地图对象 id（`city_1`），`talk_to_person` 填人物 id（**可以是别的行星上的人**）；`dock_city` 留空表示任意太空城；`install_upgrade` 留空表示任意装备，否则填 `port_session.UPGRADES` 的键（`computer` / `fuel` / `shield` / `thruster` / `capture_net`） |
| `target_name` / `target_planet` | 可选，仅 `talk_to_person`。编辑器按全项目人物索引自动填好的可读提示（人物名与所在地），只用于任务清单 tooltip 与接取提示，**不参与匹配**。手写数据可以省略 |
| `target_planet_id` | 可选，仅 `talk_to_person`。目标人物所在行星的 `planet_id`（事件 JSON 顶层的 `planet_id`）。**人物 id 允许跨行星重名**（老数据里每颗星都有 `person_1`），填了它就只在同一颗星上交谈才计数；留空则退回旧的「只按 id 匹配」 |
| `position` / `radius_m` | 仅 `arrive_point`：目标点（米）与判定半径 |
| `target_mass_kg` | 仅 `recycle_mass`：需要累计回收的物资质量（kg），进度条上限就是它 |

### 15.3 已实现类型

| type | 判定 | 触发方式 |
| --- | --- | --- |
| `arrive_point` | 飞船与 `position` 的距离 ≤ `radius_m` | 连续型，进入时 +1 |
| `arrive_target` | 飞船与该对象距离 ≤ 对象自身半径（city 用 `docking_radius_m`，planet 用 `radius_m`）＋ `radius_m` | 连续型 |
| `talk_to_person` | 与指定人物对话结束（`note_talk`）。目标人物可以在其它行星上：`note_talk(person_id, planet_id)` 比对人物 id；配置了 `target_planet_id` 时还要求是同一颗星（人物 id 跨行星重名也能区分） | 事件型 |
| `dock_city` | 有飞船 `voyage_finished` 且 `arrival_source` 属于 `cities` | 事件型（轮询观察） |
| `install_upgrade` | 船坞安装成功一件装备（`PortController._install_upgrade` → `note_upgrade`），`target` 为空表示任意装备 | 事件型（事件推入） |
| `recycle_mass` | 捕捉网擦除并回收的物资，按 kg 累加到 `target_mass_kg`（`main._note_recovered` → `note_recycle`） | 事件型（事件推入） |

`recycle_mass` 的进度单位是 kg 而不是次数：目标脚本 `QuestRecycleMass` 把 `count` 覆盖成 `target_mass_kg`，于是 `required` 直接是目标质量、`progress` 是已回收质量，任务清单自动显示 `x/y kg`（`quest_row.gd` 按 `type` 补单位）。回收量取的是网的 `absorbed_mass_kg`（已按 `capture_efficiency` 折算），空网回收返回 0、不推进。

`install_upgrade` 特意不做成轮询观察槽位：装备装好之后会一直在槽位上，接任务时若已装着就没法再「装一次」；改成安装动作推入后，接任务后再装才算数，`count: 2` 也成立（捕捉网可重复安装，其它装备要分别装不同的）。安装失败（信用点不足、槽位已占、同类已装）不会推进。

连续型用 latch：满足时 +1 并锁定，离开后解锁才能再次计数，因此 `count=2` 的「到达两次」成立而不会一帧加满。接取瞬间已满足的情况视为已消费，避免站在目标点里接任务立刻完成。

**新增一种任务 = 写一个 `extends QuestObjective` 的脚本 + 在 `TYPES` 里注册一行**，无需改管理器、清单或存档。

### 15.4 奖励与存档

奖励只在完成瞬间结算一次：`QuestManager._settle_reward()` 先发信用点（`PortController.session.add_credits(reward_credits)`），再处理装备解锁（`reward_unlock` → `session.unlock_equipment()`）；拿不到会话时只告警不伪造余额。存档 `save_manager` 的 `quest_state` 保存全部任务状态、进度与委托人（`person` / `person_name`，待复命的委托读档后要认得该找谁），`unlocked_equipment` 单独保存解锁结果（v5），旧档缺字段按「无额外解锁」处理，读档不会重发奖励或重复解锁。

### 15.5 需复命委托（`requires_return`）

状态机从两态变成三态：

```
active ──目标达成 + requires_return=false──> completed（当场结算奖励）
   │
   └──目标达成 + requires_return=true──> awaiting_return ──回到委托人处 note_talk──> completed
```

- 达成瞬间只发 `quest_ready_to_return`，`_settle_reward()` 与 `quest_completed` 都推迟到 `note_talk(person_id)` 且 `person_id` 等于接取时记录的委托人；
- `awaiting_return` 的委托仍算「在玩家头上」：`active_quests()` 会返回它，HUD 清单不消失，行里显示琥珀色的「待复命 / 回报」而不是绿色打勾（`quest_row.gd` 三态渲染）；
- 找错人（`note_talk` 传了别的人物 id）不会结算；
- `talk_to_person` + `requires_return` 的组合是「说一次算达标，再说一次才复命」，语义上就是当面汇报；
- `PortController._conversation_lines()` 在交谈前会把待复命委托的 `return_line` 接到台词末尾，`_on_dialogue_queue_finished()` 先 `note_talk` 再优先展示这份刚交掉的委托（面板显示「已复命 · 奖励已发放」），不会被同一人物的其它委托顶掉；
- 存档校验 `is_state_valid()` 接受 `awaiting_return`，并校验可选 `person` 是字符串。

### 15.6 任务清单 HUD

`scenes/ui/quest_list.tscn` 挂在 `HUD/Root/QuestList`，位于舰队栏下方（舰队栏实际高度 54，清单 `offset_top=60`）。标题栏是折叠按钮，文案 `任务 (n)`；body 是 `ScrollContainer + VBoxContainer`，每行由 `quest_row.tscn` 渲染（标题、`ProgressBar`、`x/y`、完成标记）。没有进行中任务时整块隐藏。空间物体信息面板打开时（同占左上角），清单整体下移到 `offset_top=192`，收起还原——由 `space_object_info.gd` 的 `panel_visibility_changed` 信号驱动。

面板高度跟随内容：`_fit_height()` 按行数算 `offset_bottom = offset_top + 16 + 24 + min(行数×22 + 行距×2, 208)`，超过 208 才出现滚动，折叠时只留标题栏。进度条在 `quest_row.tscn` 里用 `BarBackground`/`BarFill` 两个 `StyleBoxFlat` 着色（深底 + 青色填充），空进度也能看出轨道。

### 15.7 人物页与委托领取

港口「人物」页不再有合作/竞争关系：`diplomacy.relations` 字段已从数据中删除，`relation_edge.tscn` 一并移除，人物卡片改用 `GridContainer`（4 列、104×118、可滚动）散列排布，不再使用 JSON 里的归一化坐标。

点击头像 → `PortController._select_person` → 用主场景 `DialogueWindow` 播放该人物的 `dialogue`（缺省用「名字 + 描述」兜底，时长按字数 2.0–5.5 秒）→ `queue_finished` 后调用 `QuestManager.note_talk(person_id, planet_id)`，若该人物还有**没接过、没办完**的委托则弹出 `scenes/ports/quest_offer.tscn` 领取面板（标题/委托人/描述/目标次数/奖励/接受/放弃）。

**已领取、待复命、已完成的委托不再重复展示**：`_pick_quest()` 只返回 `QuestManager.state()` 里 status 为空（即从未接取）的委托，一份都不剩就返回空字典，交谈结束直接不弹面板（进度与完成记录看 HUD 任务清单）。对话框里的台词同样按状态过滤——`dialogue` 是每次交谈都说的招呼语，可选的 `quest_greeting` 只在「这次真能领到新委托」时补播；待复命时只播 `dialogue` + `return_line`，不会再推销旧委托。`QuestManager` 未就绪时面板进入降级态而不是崩溃。

退出面板有三个等价入口：右上角 ✕（`%CloseButton` → `close_pressed`）、底部「放弃」（`%DeclineButton` → `decline_pressed`）、以及 Esc。三者都只关闭窗口、不写任何委托状态（`port_view._on_quest_offer_dismissed()`），之后还能再找同一人物重领。面板是模态的：打开时 Esc 被 `quest_offer._input()` 的 `accept_event()` 吃掉，不会连带打开暂停菜单；点击面板外的遮罩只被吸收、不关闭面板。

测试：`tests/quest_system_test.gd`（接取、五种类型、计数与 latch、奖励只发一次、UI 折叠与进度条、存档往返、非法配置拒绝）、`tests/port_people_test.gd`（无 relations、网格不重叠、真实点击开对话、面板出现、接受后不可重复接取、已接取/已完成不再弹面板、`quest_greeting` 只在有可接委托时补播）。

### 15.8 条件台词与剧情标记（`speech` / `StoryConditions` / `StoryState`）

**要解决的问题**：同一个角色在流程不同阶段要说不同的话——没接委托时推销、接了之后闭嘴、办完之后道谢——靠 `dialogue` 一个静态数组表达不了。做法是把台词变成「**带条件的候选表**」，交谈时按顺序取第一条成立的。

**三层结构**（缺一层都会塌）：

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 条件求值 | `scripts/story/story_conditions.gd` | 纯静态 `evaluate(when, ctx) -> bool`，只认白名单键，不解析表达式字符串 |
| 台词匹配 | `port_controller._pick_speech()` | 按数组顺序取第一条 `when` 成立、且没被 `once` 记过账的条目 |
| 状态持久化 | `scripts/story/story_state.gd`（主场景 `StoryState` 节点） | `flags` 标记、`seen` 已播台词、`visited` 去过的行星，随存档保存 |

**匹配规则**（顺序即优先级）：

1. 人物写了 `speech` 就完全接管台词，**不再读 `dialogue` / `quest_greeting`**（即使一条都不成立也不回落到旧字段——写清楚比猜意图重要）。
2. 逐条判断：`once` 且已播 → 跳过；`when` 不成立 → 跳过；剩下第一条就用它。
3. 真正入队播放后（`_start_conversation` 里 `queued > 0`）才 `_commit_speech()`：写 `set_flags`、给 `once` 记账。单纯求值（预览、测试）不会污染存档。
4. 建议把**条件最具体**的放最上面、无条件兜底放最后。一条没有 `once` 的无条件条目会永远压住它下面的所有条目。

**条件键白名单**（全部 AND，列表内全部满足）：

| 键 | 值 | 含义 |
| --- | --- | --- |
| `quests_done` / `quests_active` / `quests_awaiting` | 委托 id 数组 | 全部已完成 / 任一进行中 / 任一待复命 |
| `quests_untouched` | 委托 id 数组 | 任一从未接取 |
| `flags` | `{name: bool}` | 剧情标记逐项相等 |
| `stage_min` | 整数 | 教程阶段下限 |
| `credits_min` | 整数 | 信用点下限 |
| `has_equipment` | 装备 id 数组 | 当前船已装全部命中 |
| `unlocked_equipment` | 装备 id 数组 | 已解锁全部命中 |
| `planet_id` | 字符串 | 当前所在行星 |
| `visited` | planet_id 数组 | 去过的地方全部命中 |
| `offerable_quest` | 布尔 | 这次交谈是否真能领到新委托（运行时注入） |

ctx 由 `port_controller._story_context(person)` 一次性组装（`QuestManager.status_map()`、`PortSession` 的信用点/解锁、`ProgressionManager.stage`、船上的 `upgrade_slots`、`StoryState` 的标记与足迹）。求值器不碰节点树，所以可以脱离场景单测。

**剧情标记**：`StoryState.flags` 是唯一的跨系统状态载体。写入源只有三处——台词条目的 `set_flags`、进港时的 `visited`、以及调试/测试。任务完成不要另写标记，条件里直接用 `quests_done`。

**存档**：`VERSION` 升到 6，快照多一段 `story_state: {version, flags, seen, visited}`；`_read_save` / `_compatible` 的白名单同步加 5、6。旧档缺这段时按「没有任何标记」处理，不会判损坏。「回档到上次起航」复用同一份快照，因此标记与已播台词会一起回退——这是想要的行为：撞毁重来不该白听一段剧情。

**编辑器**：新增「台词」页（`_build_speech_tab`）。顶部选人物，左侧列出该人物的候选（显示 id + 条件摘要 + 是否一次性），右侧填 `id` / `when` / `lines` / `set_flags` / `once`。`when` 用「每行 `key = 值`」的文本：列表键逗号分隔，`flags` 写 `name:true`，数字键写整数，`offerable_quest` 写 true/false。上下移动即调优先级。保存前 `collect_speech_errors()` 会拦下未知字段、未知条件键、空台词、重复 id，以及**引用了不存在的委托 id**——这类错误在游戏里表现为「这个人再也不说话」，很难查。

**测试**：`tests/story_dialogue_test.gd`（56 项：每个条件键的成立/不成立、顺序命中、`once` 记账、`set_flags`、`speech` 不成立时不回落旧字段、旧数据走旧路径、真实数据下任务完成后换台词、状态往返与非法状态拒绝、快照带 `story_state`、版本为 6）。`tests/port_people_test.gd` 覆盖真实数据下「有委托时补播介绍语、接取后不再播」。编辑器侧 `quest_editor_test.py` 覆盖条件文本往返与结构校验。
