# 地图与事件数据导入指南

> 适用对象：需要把「地图 JSON」和「行星 / 太空城事件 JSON」放进 Godot 项目并让游戏实际生效的人。
> 产出这些文件的工具：`tools/map_editor.py`（画地图）+ `tools/quest_editor.py`（配事件 / 人物 / 委托）。
> 项目内所有路径以 `space/`（`project.godot` 所在目录）为根；游戏内 `res://` 就是根，`user://` 是运行时的用户目录。

---

## 1. 两类 JSON 的分工

游戏世界由**两层数据**拼起来，缺任何一层都不完整：

```
maps/*.json                        地图层：世界骨架（坐标、半径、引力、港口位置、CG 指向）
├─ cg_data_path ──────────────────────────────────────┐
└─ objects[]
   ├─ type = "planet"  ──fields.interaction_data_path──┐
   ├─ type = "city"    ──fields.interaction_data_path──┤
   ├─ type = "asteroid"（无交互数据）                   │
   └─ type = "debris"  （无交互数据）                   │
                                                        ▼
data/planets/*.json                内容层：这颗行星 / 这座城有什么
├─ events[]            港口「事件」页的条目
└─ diplomacy.persons[] 「人物」页的人物：台词、可领取的委托

data/cg/<地图名>.json              演出层（可选）：只属于这张地图的 CG
└─ cgs[]               图片 + 文本 + 时长 + 播放条件
```

- **地图 JSON 决定「东西在哪」**：对象类型、米制坐标、半径、引力参数、以及每个对象的 `interaction_data_path`。
- **事件 JSON 决定「到了以后能干什么」**：事件文案、港口人物、人物台词、人物身上的委托。
- **CG JSON 决定「什么时候演哪一段」**：图片、文本、停留时长与触发条件。
- **事件 JSON 的连接点是 `interaction_data_path`**：它必须写成 `res://data/planets/xxx.json`，不允许 `..`、不允许反斜杠、不允许指向 `data/planets/` 以外的地方（`scripts/navigation/map_loader.gd` 会直接拒绝整张地图）。
- **CG 的连接点是地图根节点 `cg_data_path`**：只允许 `res://data/cg/` 下的直属 JSON；CG 文件里再用根节点 `map` 反向声明归属，形成双向绑定。
- 多个地图对象可以共用同一份事件 JSON（例如 `default_map.json` 里 `planet_1/2/3` 都指向 `planet_a.json`）。共用意味着改一处三处都变；想拆开就用编辑器的「复制为新文件」。

## 2. 放置位置速查

| 文件 | 项目内位置 | 游戏内路径 | 谁在读它 |
| --- | --- | --- | --- |
| 事件 JSON | `data/planets/<名字>.json` | `res://data/planets/<名字>.json` | `planet.gd` / `flat_nuclear_city.gd` 的 `interaction_data_path` → `PortController` → `PortSession` |
| 地图专属 CG | `data/cg/<地图名>.json` | `res://data/cg/<地图名>.json` | 地图根节点 `cg_data_path` → `CgController._sync_map_config()` |
| 全局 CG（可选） | `data/cg.json` | `res://data/cg.json` | `CgController.config_path`，所有地图都会加载 |
| 世界地图（内置默认） | `maps/default_map.json` | `res://maps/default_map.json` | `MapLoader.load_map(true)` 的回退地图 |
| 用户自定义地图（可选） | `%APPDATA%\Godot\app_userdata\Space\space_map_v1.json` | `user://space_map_v1.json` | 优先级最高，存在就顶掉内置地图 |
| 教程地图 · 城市 | `maps/city_teach.json` | `res://maps/city_teach.json` | `ProgressionManager.CITY_MAP_PATH` |
| 教程地图 · 行星 | `maps/plante_teach.json` | `res://maps/plante_teach.json` | `ProgressionManager.ORBIT_MAP_PATH` |

结论只有一句：**事件 JSON 只能放 `data/planets/`；地图 JSON 要么放 `maps/`（进包），要么放用户目录（不进包）。**

## 3. 用编辑器配置一份数据（推荐流程）

`tools/quest_editor.py` 的设计前提是「没有地图就没有上下文」，所以它的操作是严格分步的：

1. **打开地图 JSON**（顶栏第一个按钮）。没打开地图之前，左右两侧的列表、页签、保存按钮全部是禁用的——这是刻意设计，避免配出一份谁都不引用的事件文件。
2. **左侧选中一个行星或太空城**。列表的「事件数据」列会告诉你当前状态：
   - `已有`：`interaction_data_path` 指向的文件存在，可以直接编辑；
   - `未配置`：没有 `interaction_data_path`；
   - `文件缺失`：写了路径但文件不存在；
   - `共用 N 个对象`：多个对象引用同一份文件，改一份等于改 N 份。
3. **创建事件 JSON**（或「选择已有 JSON」）。创建时会弹出保存对话框，默认位置就是 `data/planets/`、默认文件名为 `<对象 id>.json`，也可以改名；确认后写入一份合法空骨架，并**自动把新路径写回地图对象的 `interaction_data_path`**。这一步是编辑器唯一会改动地图的地方（只改内存，点「保存全部」才落盘）。
4. **填写四页内容**：「事件」「人物」「委托」「台词」。委托是挂人物身上的，所以委托页顶部要先选人物。委托页的「需要返回复命」勾选框写上 `requires_return`，勾上后才能填 `return_line`（复命台词，可留空用默认句）；列表里这类委托会标「· 需复命」。委托类型选「与指定人物对话」时，目标下拉列出的是**全项目所有行星和太空城上的人物**（显示为「名字（行星 planet_id）· 人物 id」，人物 id 重名时靠括号里的 planet_id 区分），可以直接选别的星球上的人——接取后再飞过去找当事人即可，保存时写入 `target` / `target_planet_id`，并顺带写 `target_name` / `target_planet` 供界面提示。**「台词」页**同样是先选人物：一个人可以有多套台词，每套带条件，列表从上到下就是优先级（可上下移动调整），`when` 用「每行 `key = 值`」填写，规则见 5.6。
5. **点「校验」**。它跑的是和 Godot 运行时一致的规则（见第 6 节），还会交叉检查委托目标是否真的存在于这张地图里。
6. **点「保存全部」**。按需要写三份文件：事件 JSON 写到 `data/planets/`；CG JSON 写到 `data/cg/`（只有改过才写）；地图 JSON 写回你打开它时的原路径（只有绑定/切换过路径才真的写地图）。
7. 需要给新对象配一份独立数据时用「复制为新文件」：复制当前内容、改 `planet_id`、另存为新文件并切换地图引用。
8. 需要在这张地图里播 CG 时，切到**「CG 剧情」页**（地图级，与左侧选中哪个对象无关）：
   - 没绑定时显示「该地图还没有 CG 配置」，点「创建 CG 配置」→ 在 `data/cg/` 生成 `<地图名>.json`，并把 `res://data/cg/<地图名>.json` 写进地图根节点 `cg_data_path`；
   - 「新增」一条 CG，填 `image`、`text`、`duration`，选四种播放条件之一（进入地图 / 进入行星或太空城 / 完成某个任务 / 到达某个地点），按条件类型补 `map`、`object`、`quest` 或 `position + radius_m`；
   - 「应用」后「保存全部」，CG 文件与地图里的绑定一起落盘。校验会拦下「指向不存在的对象」「半径/时长非法」「重复 id」，图片缺失只给提示。

编辑器默认就在项目目录里读写，所以**第 6 步做完，文件已经在 Godot 项目里了**。只有当数据是别人给你的、或者你在别处编辑过，才需要走第 4 节的复制步骤。

### 3.1 保存会做哪些「格式化」动作

保存不是「原样写回」，而是按编辑器内部模型重新序列化，语义不变但字节会变：

- 缩进统一成 2 个空格（原来用制表符的文件会被规范化）；
- `dock_city` 这类可留空的 `target` 会补成 `"target": ""`，与缺省等价；
- 人物里编辑器不认识的旧字段（如 `position`）原样保留；
- 人物的 `dialogue` / `quest_greeting` / `quests` 被清空时会删除该键，而不是留一个空数组。

所以第一次保存后看到 `git diff` 里满是缩进变化是正常的；**纯编辑事件内容不会重写地图**，地图文件只有在绑定/切换 `interaction_data_path` 时才会变。

## 4. 把 JSON 放进 Godot 的具体步骤

### 4.1 事件 JSON

1. 把文件复制到 `D:\Godot\Project\space\data\planets\`（文件名建议就用 `<对象 id>.json`）。
2. 回到 Godot 编辑器，FileSystem 面板会自动刷新；没刷新就右键根节点 → 「重新扫描文件系统」。
3. **不需要设置任何导入选项**。JSON 是纯文本，游戏用 `FileAccess` 在运行时直接读，不进资源导入管线。
4. 让引用生效：地图对象的 `fields.interaction_data_path` 必须写成 `res://data/planets/<文件名>.json`。用编辑器创建会自动写；手工加的对象也可以用 `map_editor.py` 的属性面板填。
5. 导出时必须被包进去，见 4.3。

### 4.2 地图 JSON —— 四种投放方式，按场景选一种

**A. 我自己玩，不想打包（迭代最快）**

复制到用户目录：

```
%APPDATA%\Godot\app_userdata\Space\space_map_v1.json
```

即 `C:\Users\<你的用户名>\AppData\Roaming\Godot\app_userdata\Space\space_map_v1.json`。

这张地图优先级最高，游戏一定先读它；`maps/` 里的内置地图只在你删掉它之后才用。好处是不用重新导出、不用改项目；坏处是别人拿不到这张图。

**B. 打包给玩家（改成默认世界）**

用你的地图覆盖 `maps/default_map.json`。游戏在「开始新游戏 → 世界阶段」调 `load_world_map()`，没有用户地图时就回退加载它。

**C. 改教程用的地图**

教程阶段固定读 `res://maps/city_teach.json`（太空城入港教程）和 `res://maps/plante_teach.json`（行星入轨教程）。把对应文件替换掉即可，注意教程里的目标对象 id 不能改名，否则教程的步骤判定和高亮会找不到目标。

**D. 一张全新的地图文件**

放进 `maps/` 后，需要有一行代码引用它：

- 当世界地图用：覆盖 `default_map.json`，或把它复制成用户目录里的 `space_map_v1.json`；
- 当教程地图用：改 `scripts/progression/progression_manager.gd` 顶部的 `CITY_MAP_PATH` / `ORBIT_MAP_PATH` 常量。

### 4.3 导出设置（只做一次，已配好）

`export_presets.cfg` 的 `include_filter` 必须把 JSON 一起打进包：

```ini
include_filter="data/*.json,data/planets/*.json,maps/*.json"
```

`.json` 不是 Godot 资源，`export_filter="all_resources"` 不会自动收录它们。漏了 `maps/*.json` 的后果是：导出版里找不到内置地图，一进世界就是空场景。本仓库已经补上 `maps/*.json`。

### 4.4 生效时机与存档影响

| 改了什么 | 什么时候生效 |
| --- | --- |
| 事件 JSON（事件文本、人物、委托） | 主场景重新加载后。`PortController` 的 `PortSession` 在一次场景生命周期内缓存已读过的行星数据，所以最省事的做法是**退出到主菜单再进游戏**（或重启游戏） |
| 地图 JSON | 开始新游戏 / 进入世界地图 / 切换教程阶段时重新读取 |
| 地图文件被改坏 | `map_load_error = true`，游戏不替换世界，`SaveManager` 会提示「地图文件无效或无法读取」并**关闭保存与自动保存**，保护原存档 |

**存档会失效的情况**：存档里记录了地图指纹（`map_hash`，忽略只影响外观的 `texture_id`）。只要地图 JSON 的内容有任何变化——包括编辑器刚给你写进去的 `interaction_data_path`——旧存档读档时会被判定为不匹配而读取失败（原存档文件保留，自动保存已关闭）。

所以推荐的开发节奏是：

- 只调事件文案、人物、委托 → 存档不受影响，直接改；
- 改地图（加对象、改坐标、建新事件文件并绑定）→ 默认按「这张图是新世界」处理，配完请开新游戏验证，不要指望旧档还能接着玩。

## 5. 数据结构与字段

### 5.1 地图 JSON

顶层：

```json
{
  "version": 1,
  "cg_data_path": "res://data/cg/default_map.json",
  "objects": [ ... ],
  "ship": { "position": [-273092.7, -71396.4], "velocity": [0.0, 0.0] }
}
```

`cg_data_path` 可选，是本图专属 CG 文件的绑定（格式见 5.7）。`objects[]` 的公共字段：`type`、`id`、`position: [x, y]`（米，Y 向下）、`fields: {}`。

| type | `fields` 允许的键 |
| --- | --- |
| `planet` | `display_name`、`radius_m`、`field_height_m`、`surface_gravity`、`max_gravity_radius_m`、`interaction_data_path`、`texture_id` |
| `city` | `display_name`、`rotation_degrees_m`、`city_size_m`、`gravity_height_m`、`port_offset_m`、`docking_radius_m`、`dock_offset_m`、`interaction_data_path` |
| `asteroid` | `initial_velocity`、`radius_m`、`mass_kg`、`style_index`、`texture_id`（历史字段 `mineral_id` / `mineral_unit_mass` 兼容保留） |
| `debris` | `initial_velocity`、`radius_m`、`mass_kg`、`debris_count`、`debris_size_m`、`minimum_fragment_pixels`、`texture_id` |

注意 `fields` 的键名是**白名单**：多写一个不认识的键，整张地图会被判无效。

### 5.2 事件 JSON 顶层

```json
{
  "schema_version": 1,
  "planet_id": "planet_a",
  "name": "晨曦港 · 原型示例",
  "events": [ ... ],
  "diplomacy": { "persons": [ ... ] }
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `schema_version` | 是 | 固定 `1` |
| `planet_id` | 是 | 非空字符串。**建议与文件名一致**（游戏只做非空校验，不做一致性校验，但混用日后难查） |
| `name` | 是 | 港口标题栏显示的名字 |
| `events` | 是 | 数组，可为空数组 |
| `diplomacy` | 是 | 对象，必须有 `persons` 数组，可为空数组 |

### 5.3 `events[]`

| 字段 | 说明 |
| --- | --- |
| `id` | 事件 id，同一文件内唯一 |
| `title` | 卡片标题 |
| `body` | 卡片正文 |

### 5.4 `diplomacy.persons[]`

| 字段 | 说明 |
| --- | --- |
| `id` | 人物 id，同一文件内唯一 |
| `name` | 姓名 |
| `role` | 身份 |
| `description` | 描述，会出现在人物详情里 |
| `portrait` | 头像 `res://` 路径，允许空串（空则用默认底板） |
| `dialogue` | 可选，字符串数组，每项一句台词；点人物头像时逐句播放，**每次交谈都说** |
| `quest_greeting` | 可选，字符串数组，委托介绍语；**只有这次真能领到新委托时才补播**，已领取/待复命/已完成都不再说 |
| `speech` | 可选，台词候选数组，见 5.6。**一旦写了就接管这台词**（`dialogue` / `quest_greeting` 不再生效） |
| `quests` | 可选，委托数组，见 5.5 |

`position: [0.5, 0.5]` 这类旧字段已经不再使用（人物卡片改成 `GridContainer` 网格排布，不读坐标），保留也不会报错，但写了没有效果。

### 5.5 `quests[]`

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | **全局唯一**（`QuestManager` 按 id 接取，重复会被拒绝） |
| `title` | 是 | 清单与领取面板标题 |
| `description` | 是 | 目标描述 |
| `type` | 是 | 判定类型，必须在 `QuestManager.TYPES` 注册 |
| `count` | 是 | 需要达成次数，≥ 1 |
| `reward_credits` | 是 | 完成时一次性加到舰队共享信用点，≥ 0 |
| `reward_unlock` | 否 | 完成时解锁 `data/equipment.json` 里 `requires_unlock=true` 的装备 id（如 `hangar`） |
| `requires_return` | 否 | 布尔。`true` 时目标达成只进入「待复命」，玩家必须回到该委托人处交谈才完成并领奖；缺省 `false` |
| `return_line` | 否 | 仅 `requires_return=true` 时有意义：复命时补播的一句委托人台词，留空用默认台词 |
| `target` | 按类型 | 见下表 |
| `target_name` / `target_planet` | 否 | 仅 `talk_to_person`。编辑器自动填的人物名与所在地，只供任务清单 tooltip 与接取提示显示，不参与判定；手写可省略 |
| `target_planet_id` | 否 | 仅 `talk_to_person`。目标人物所在行星的 `planet_id`（事件 JSON 顶层的那个）。人物 id **可以跨行星重名**，填了就只在同一颗星上交谈才计数；留空退回只按 id 匹配 |
| `position` / `radius_m` | 按类型 | 见下表 |

| `type` | 判定 | `target` 含义 | 额外字段 | 触发方式 |
| --- | --- | --- | --- | --- |
| `arrive_point` | 飞船与 `position` 距离 ≤ `radius_m` | 不使用 | `position: [x, y]`（米，与地图同一坐标系）、`radius_m > 0` | 连续型，进入时 +1 |
| `arrive_target` | 飞船与对象距离 ≤ 对象自身半径 + `radius_m` | 地图对象 id（`planet_1` / `city_1`） | `radius_m ≥ 0` | 连续型 |
| `talk_to_person` | 与 `target` 人物对话结束 | 人物 id，**可以是任意行星上的人**（先在某处接委托，再飞去别处找当事人）；同名人物用 `target_planet_id` 区分 | `target_planet_id`（可选，人物所在行星） | 事件型 |
| `dock_city` | 任一飞船在太空城停泊 | 留空 = 任意太空城；否则填 city 对象 id | 无 | 事件型 |
| `install_upgrade` | 在船坞装上 `target` 指定的装备 | 留空 = 任意装备；否则填装备 id：`computer` / `fuel` / `shield` / `thruster` / `capture_net` | 无 | 事件型 |
| `recycle_mass` | 捕捉网擦除并回收的物资累计到目标质量 | 不使用（改用 `target_mass_kg`） | `target_mass_kg > 0`（kg，进度条上限） | 事件型 |

```json
{
  "id": "q_install_shield",
  "title": "补一层护盾",
  "description": "去太空城船坞装上霍普尔盾，再回来找我。",
  "type": "install_upgrade",
  "target": "shield",
  "count": 1,
  "reward_credits": 150
}
```

`recycle_mass` 示例：

```json
{
  "id": "q_recycle_2000",
  "title": "回收两千公斤废料",
  "description": "用捕捉网装满碎片，让网体落到行星上，回收到的物资都算数。",
  "type": "recycle_mass",
  "target_mass_kg": 2000,
  "count": 2000,
  "reward_credits": 300
}
```

进度按 kg 累加：每张网撞上行星时，网里 `absorbed_mass_kg`（已按捕获效率折算）加到进度上，空网回收不加。`count` 会被 `target_mass_kg` 覆盖，写不写都一样（编辑器会自动同步）。

需要「回来复命」的委托加 `requires_return: true`：

```json
{
  "id": "q_return_reports",
  "title": "带回一页签章",
  "description": "在任意太空城停泊登记，把签章页带回来。",
  "type": "dock_city",
  "target": "",
  "count": 1,
  "reward_credits": 150,
  "requires_return": true,
  "return_line": "签章拿到了？……好，这页纸值一趟航程。"
}
```

这类委托达成目标后不会变成「已完成」，而是停在**待复命**：任务清单里显示琥珀色的「待复命 / 回报」，奖励一分不发。玩家得回到委托人所在港口，点这位人物的头像把对话读完，才结算奖励并发 `quest_completed`。复命只认接取时记录的那位委托人：换个人对话不会结算。`return_line` 只在 `requires_return: true` 时才写，写了也不会在别处用到（编辑器会直接拦下）。

`install_upgrade` 判定的是**安装动作**（`PortController` 安装成功时推一次），不是「槽位上有没有这件装备」：因此接任务之前就装好的装备不算，装上之后一直带着也不会重复计数；`count: 2` 需要装两件（捕捉网可以重复装，其它装备要分别装不同的）。

新增一种类型 = 写一个 `extends QuestObjective` 的脚本 + 在 `QuestManager.TYPES` 里加一行；`quest_editor.py` 的 `QUEST_TYPES` 也要同步加，否则编辑器不给选。

### 5.6 台词候选（`speech[]`）

同一角色在不同阶段说不同的话。**写了 `speech` 就完全接管台词**：`dialogue` 与 `quest_greeting` 不再生效（即使一条都不成立也不回落）。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 否 | 同一人物内唯一；可省略，省略时按序号定位，`once` 记账也用它 |
| `when` | 否 | 条件对象，缺省 = 无条件成立 |
| `lines` | 是 | 字符串数组（也接受单个字符串） |
| `once` | 否 | `true` 时只播一次，播过记入存档 |
| `set_flags` | 否 | `{name: true/false}`，播完写入剧情标记，供后续 `when.flags` 用 |

只允许上面五个字段，多写一个会被拒绝（多半是拼错）。

**顺序即优先级**：按数组顺序取第一条成立的。条件最具体的放最上面，无条件兜底放最后——一条没有 `once` 的无条件条目会永远压住它后面的所有条目。

| `when` 键 | 值 | 含义 |
| --- | --- | --- |
| `quests_done` | 委托 id 数组 | 全部已完成 |
| `quests_active` | 委托 id 数组 | 任一进行中 |
| `quests_awaiting` | 委托 id 数组 | 任一待复命 |
| `quests_untouched` | 委托 id 数组 | 任一从未接取 |
| `flags` | `{name: true/false}` | 标记逐项相等 |
| `stage_min` | 整数 | 教程阶段下限 |
| `credits_min` | 整数 | 信用点下限 |
| `has_equipment` | 装备 id 数组 | 当前船已装 |
| `unlocked_equipment` | 装备 id 数组 | 已解锁 |
| `planet_id` | 字符串 | 当前所在行星 |
| `visited` | planet_id 数组 | 去过的地方 |
| `offerable_quest` | true/false | 这次交谈是否真能领到新委托 |

```json
"speech": [
  {
    "id": "after_hangar",
    "when": { "quests_done": ["q_city_hangar"] },
    "lines": ["你把它开回来了？比我预想的快。"],
    "once": true,
    "set_flags": { "keeper_thanked": true }
  },
  {
    "id": "offer",
    "when": { "offerable_quest": true },
    "lines": ["我这儿有份活：去平面核城市找机库管理员。"]
  },
  {
    "id": "idle",
    "lines": ["你好。"]
  }
]
```

编辑器「台词」页可以直接配这套东西：左边是候选列表（显示条件摘要与是否一次性），上下移动就是调优先级，`when` 用「每行 `key = 值`」的文本填写。

### 5.7 地图级 CG（`cg_data_path`）

地图根节点绑定一份 CG 配置，让这段演出只属于这张图：

```json
{
  "version": 1,
  "cg_data_path": "res://data/cg/default_map.json",
  "objects": [ ... ]
}
```

```json
{
  "version": 1,
  "map": "default_map",
  "cgs": [
    {
      "id": "city_gate",
      "image": "res://assets/cg/city_gate.png",
      "text": "晨曦港的闸门在你面前缓缓打开。",
      "duration": 4.5,
      "trigger": { "type": "enter_object", "object": "city_1", "kind": "city" }
    }
  ]
}
```

| 检查 | 规则 | 不满足的后果 |
| --- | --- | --- |
| `cg_data_path` 格式 | `res://data/cg/` 开头、`.json` 结尾、无 `..`、无反斜杠、无子目录 | **整张地图判为无效**（`MapLoader.valid_cg_path`） |
| 文件是否存在 | 由编辑器 `--check` 与运行时报警告 | 地图能进，但这条 CG 不播 |
| 根节点 `map` | 与地图文件名（去 `.json`）一致；留空则不校验 | 不一致时**整份 CG 文件被忽略**并告警 |
| `trigger.object` / `quest` | 建议取本图对象 id / 本图事件 JSON 里的委托 id | 条件永远不命中（不会崩） |

四个触发条件（`map_enter` / `enter_object` / `quest_complete` / `reach_point`）与字段表的完整说明见 **`docs/CG剧情配置指南.md`**。CG 与全局 `data/cg.json` 会合并加载，地图专属条目的 id 内部带 `<地图名>/` 前缀，存档不会串。

## 6. 校验规则

编辑器会在保存前把下面两类问题全部报出来；Godot 运行时的行为也一并列出，方便对照。

### 6.1 硬失败（整份数据不可用）

| 检查 | 后果 |
| --- | --- |
| 地图 `version` 不是 1、`objects` 不是数组或超过 1000 项 | 整张地图不加载 |
| 对象 `type` 不在四种里、`id` 不合法或重复、`position` 不是两个有限数字 | 整张地图不加载 |
| `fields` 出现白名单以外的键 | 整张地图不加载 |
| `interaction_data_path` 不是 `res://data/planets/*.json` | 整张地图不加载 |
| `cg_data_path` 不是 `res://data/cg/*.json`（含子目录 / `..` / 反斜杠） | 整张地图不加载 |
| 地图对象引用的 JSON 不存在 | 入港失败，港口显示「港口数据不可用」 |
| 事件 JSON `schema_version` 不是 1、缺 `planet_id` / `name` | 入港失败 |
| `events` 不是数组、`diplomacy.persons` 不是数组 | 入港失败 |
| 事件缺 `id` / `title` / `body`，或 id 重复 | 入港失败 |
| 人物缺 `id` / `name` / `role` / `description`，或 id 重复 | 入港失败 |
| 人物 `dialogue` / `quest_greeting` 不是字符串数组 | 入港失败 |
| 人物 `speech` 不是数组、是空数组、条目含未知字段、`lines` 为空 | 入港失败（错误行会指出第几条） |
| `speech[].when` 含未知条件键，或 `once` / `set_flags` 类型不对 | 入港失败 |
| 委托缺 `id` / `title` / `description` / `type` | 入港失败 |
| 委托 `count` 不是 ≥1 整数、`reward_credits` 不是 ≥0 整数 | 入港失败 |
| 委托 `requires_return` 不是布尔、`return_line` 不是字符串 | 入港失败 |
| 委托 `target_name` / `target_planet` / `target_planet_id` 不是字符串 | 入港失败（这三个字段可以整段省略） |

### 6.2 软失败（能进港，但那份委托领不到）

- 委托 `type` 没在 `QuestManager.TYPES` 注册 → 接取时 `push_warning("任务类型未注册")` 后静默失败；
- `arrive_target` 的 `target` 在地图上找不到 → `validate()` 返回错误，委托加不进去；
- `arrive_point` 缺 `position` 或 `radius_m ≤ 0` → 同上；
- `talk_to_person` 的 `target` 写成不存在的人物 id → 永远无法达成（跨行星的人可以，只要 id 在任意一份 `data/planets/*.json` 里）；
- 同一个人物 id 出现在两份事件 JSON 里且没写 `target_planet_id` → 交谈时只认 id，在哪颗星上跟同名的人说话都会计入；编辑器会顺手补上 `target_planet_id`（标签里带行星 id），手写数据建议照做；
- 委托 `id` 和别的委托撞了（**跨文件也算**）→ 第二份接不了；更隐蔽的是已经接了 A 星那份后，B 星同 id 的委托会显示成「已接取 · 进度 0/1」、接受按钮置灰——运行期任务表只按 id 建键，所以 id 必须全项目唯一，编辑器保存前会拦下。

编辑器把 6.2 里能静态判断的（类型未注册、目标不存在、坐标缺失、id 重复）都升级成了保存前报错，所以正常流程下不该产出这类数据。

## 7. 常见问题对照

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 一进世界地图就是空的/只有默认对象 | 用户地图存在但无效，或导出版没打进 `maps/` | 删掉 `space_map_v1.json` 重试；检查 `include_filter` 是否含 `maps/*.json` |
| 屏幕提示「地图文件无效或无法读取，保存已关闭」 | 地图校验没通过 | 跑 `python tools/quest_editor.py --check` 定位具体对象与字段 |
| 泊船后港口标题显示「港口数据不可用」，错误行给出具体原因 | 事件 JSON 校验失败或文件不存在 | 按错误行提示修，或跑 `--check`；确认 `interaction_data_path` 与实际文件一致 |
| 港口能开，但「事件」页是空的 | `events` 是空数组 | 至少加一条事件 |
| 点人物没有「领取委托」按钮 | 该人物没有 `quests`，或委托配置不合法 | 补齐 `count` / `reward_credits` / `type` |
| 委托一直不完成 | 类型与目标不匹配，例如 `arrive_target` 填了人物 id | 按 5.5 的表逐字段核对 |
| 读档失败、回到主菜单 | 地图被改过，`map_hash` 与存档不符 | 这是设计行为；用新游戏验证。原存档文件仍在 `%APPDATA%\Godot\app_userdata\Space\` |
| 地图专属 CG 完全不播 | `cg_data_path` 指向的文件不存在，或根节点 `map` 与地图名不一致 | 看控制台告警；用 `--check` 定位；确认两边地图名一致 |
| 地图换了对象 id 后 CG 不触发 | `trigger.object` 还写着旧 id | 在地图里核对 `objects[].id`，或把 `object` 改成 `*` 先跑通 |
| 改完 JSON 进游戏没变化 | 事件数据在场景生命周期内被缓存 | 退出到主菜单再进，或重启游戏 |
| 某个角色再也不说话 | 写了 `speech` 但所有 `when` 都不成立（常见：引用的委托 id 拼错、`flags` 永远没人写） | 至少留一条无条件的兜底条目；编辑器保存时会拦下不存在的委托 id |
| 新台词怎么都不出现 | 前面有更靠前且一直成立的条目压着，或这条 `once` 已经播过 | 记住「顺序即优先级」；把条件最具体的往上挪，`once` 的要看存档里的已播记录 |
| 任务都做完了，见面还在推销旧委托 | `speech` 里写了一条 `when: {offerable_quest: true}` 的条目，但前面没有兜底逻辑 | 兜底条目放最后，它会在没有可接委托时接手 |

## 8. 命令行校验（不开窗口）

```bash
# 检查 maps/ 下全部地图及其引用的事件 JSON + 地图绑定的 CG
python tools/quest_editor.py --check

# 只检查指定地图
python tools/quest_editor.py --check maps/default_map.json
```

输出形如（Windows 下是反斜杠，其他平台是 `/`）：

```
OK maps\default_map.json
  - planet_1: OK
  - city_1: OK
  - CG: 未绑定
...
```

有 `cg_data_path` 时对应行是 `  - CG(res://data/cg/default_map.json): OK`，图片缺失等只影响可玩性的问题以 `    WARN: ...` 前缀单独列出，不会让校验失败。任一硬错误即退出码 1，可以直接挂到提交前检查里。

> Windows 上如果 `python` 没装 tkinter（编辑器窗口打不开），用装了 tkinter 的解释器跑，例如 `D:\Coding\python\python.exe tools\quest_editor.py`。
